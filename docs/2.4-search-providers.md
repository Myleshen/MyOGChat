# Phase 2.4 (ext) — Pluggable web-search providers

Status: deployed (2.4 merged to `main`; 2.12 Serper + Brave `llm/context`
extensions on `feat/search-providers2`).

`web_search` is provider-agnostic. The model-facing tool name and its argument
schema (`{"query": "..."}`) are **unchanged**; only the backend that answers
changes. An ordered **fallback chain Tavily → Brave → Serper → DuckDuckGo** keeps
search working when a key is missing or a backend errors/rate-limits.

## Provider layer (`internal/tools/search.go`)

```go
type Result struct { Title, URL, Snippet string }

type Options struct {
    MaxResults int    // default 5, clamped to 1..20
    Region     string // DDG kl / Brave country / Serper gl+hl source, e.g. "us-en"
    SafeSearch string // off | moderate | strict
}

type SearchProvider interface {
    Name() string
    Search(ctx context.Context, query string, opts Options) ([]Result, error)
}
```

Providers (each holds its own `*http.Client`, 20s timeout, and a `baseURL` field
so tests can point it at an `httptest.Server`):

| provider | `Name()` | endpoint | auth | mapping |
|---|---|---|---|---|
| Tavily | `tavily` | `POST https://api.tavily.com/search` | `Authorization: Bearer` | `results[].{title,url,content}` → `Snippet=content` |
| Brave | `brave` | `GET https://api.search.brave.com/res/v1/web/search` | `X-Subscription-Token` | `web.results[].{title,url,description}`, HTML tags stripped |
| Brave (context) | `brave` | `GET https://api.search.brave.com/res/v1/llm/context` | `X-Subscription-Token` | `grounding.generic[].{url,title,snippets[]}`; snippets joined into `Snippet` |
| Serper | `serper` | `POST https://google.serper.dev/search` | `X-API-KEY` | `organic[].{title,link,snippet}` (**`link`**, not `url`) |
| DuckDuckGo | `ddg` | `GET https://html.duckduckgo.com/html/` | none (browser UA) | scrape `result__a` / `result__snippet`, decode `uddg` |

DuckDuckGo is a **keyless best-effort scrape** using only the standard library
(`regexp`/`strings`/`net/url` — no new dependency, no `golang.org/x/net/html`).
The `href` is a redirect (`//duckduckgo.com/l/?uddg=<encoded>`); the `uddg` query
param is decoded to recover the real URL. A non-200 response, zero parsed
results, or markup drift is treated as a provider failure (never a panic) so the
chain continues.

### Serper (2.12)

- `POST https://google.serper.dev/search`, header `X-API-KEY`, JSON body
  `{q, num, gl, hl}` (`gl` = country from the region, `hl` = language).
- `num` is **capped at 10**: Serper bills 10 results as 1 credit but 11–20 as 2,
  and the tool clamps to ≤20, so 10 keeps every query at 1 credit.
- Response `organic[]` maps to `Result{Title, URL: link, Snippet}` — the URL
  field is **`link`** (not `url`). `answerBox`/`knowledgeGraph` are ignored (they
  would change result-count semantics).

### Brave `llm/context` mode (2.12)

Brave's `llm/context` endpoint is a **retrieval mode of the existing Brave
provider**, not a separate provider: it shares the same key, host, and `Name()`.
It is selected by `SearchConfig.BraveContext` (env `MYOGCHAT_BRAVE_MODE=context`,
DB `brave_mode`). It calls `GET /res/v1/llm/context` with `q`, `count`,
`country`, `search_lang`, `safesearch`, and a bounded
`maximum_number_of_tokens=4096` (Brave's 8192 default is too large for a tool
result). Each `grounding.generic[]` entry's `snippets[]` are cleaned and joined
with newlines into `Result.Snippet`. An empty `grounding.generic` is a provider
error so the chain continues.

The model-facing `web_search` tool is **unchanged** in either Brave mode — the
model simply receives richer (chunked) snippets.

## Selection & fallback (`BuildSearchProviders`)

```go
type SearchConfig struct {
    Provider     string // tavily | brave | serper | ddg | auto
    TavilyKey    string
    BraveKey     string
    SerperKey    string
    BraveContext bool   // Brave llm/context (RAG) mode
    MaxResults   int
    Region       string
    SafeSearch   string
}
func BuildSearchProviders(cfg SearchConfig) []SearchProvider
func SearchActive(cfg SearchConfig) string // which provider would answer first
```

- **Explicit** `tavily` | `brave` | `serper` | `ddg` leads the chain; the other
  providers stay behind it as fallbacks.
- **`auto`** (default) → first usable of **Tavily → Brave → Serper →
  DuckDuckGo**.
- A keyed provider is **never constructed with an empty key**; a selected
  provider whose key is missing is skipped. DuckDuckGo needs no key, so the chain
  is never empty.
- **Fallback:** on provider error or empty results, log a warning and try the
  next. The chain is capped at `maxSearchChain = 4` providers and shares one
  overall `searchBudget = 25s` context, so a multi-provider turn cannot stall for
  `chain × 20s`.
- The tool is registered whenever **any** provider is usable (DDG alone counts).

`WebSearchTool` (`internal/tools/websearch.go`) keeps its `Name/Description/
Parameters/Run` contract and delegates to the resolved chain;
`formatSearchResults` takes `[]Result`.

## Configuration

Environment (read in `main.go`/`loadConfig`):

| env var | meaning | default |
|---|---|---|
| `TAVILY_API_KEY` | Tavily key (existing) | — |
| `BRAVE_API_KEY` | Brave key | — |
| `SERPER_API_KEY` | optional **server-wide** Serper key (per-user keys take precedence) | — |
| `MYOGCHAT_SEARCH_PROVIDER` | `tavily` \| `brave` \| `serper` \| `ddg` \| `auto` | `auto` |
| `MYOGCHAT_BRAVE_MODE` | `web` \| `context` (Brave `llm/context`) | `web` |
| `MYOGCHAT_SEARCH_RESULTS` | results per query (clamped 1–20) | `5` |
| `MYOGCHAT_SEARCH_REGION` | DDG `kl` / Brave country / Serper `gl`+`hl` source | `us-en` |
| `MYOGCHAT_SEARCH_SAFESEARCH` | `off` \| `moderate` \| `strict` | `moderate` |

DB settings (admin, via `GET|PATCH /api/settings`; Brave key encrypted with
`internal/secret`, mirroring the Linkwarden pattern):

- `search_provider` — provider selector (overrides the env default).
- `brave_key` — Brave API key (set/replace/clear); takes precedence over the env
  key.
- `brave_mode` — `web` | `context`; overrides `MYOGCHAT_BRAVE_MODE`.

`GET /api/settings` gains `serper_configured` (server-wide env only),
`brave_mode`, and the `serper` value in the `search_provider`/`search_active`
unions, alongside `tavily_configured`/`brave_configured`.

### Per-user Serper key (2.12)

The Serper key is **per-user** (owner request), resolved per request like the
OpenCode key: the caller's own stored key → the optional server
`SERPER_API_KEY`. It is stored encrypted (`internal/secret`) in
`users.serper_key_enc` and never returned to the SPA (only a 4-char hint).

- `GET /api/me/serper` → key status + provider list + `search_active` (any
  authenticated user).
- `PUT /api/me/serper` `{"api_key": "..."}` → set (encrypt) / clear (`""`).

The admin/global `serper_configured` reflects only the env key; a user's own key
is exposed by `GET /api/me/serper` and is only used for that user's requests.

## Frontend

A clearly-delimited, self-contained **per-user web search** block in Settings
(`static/index.html`, `#my-search-section`; wired in `static/app.js`): the
Serper key field (set/clear) plus a provider list (Tavily/Brave/Serper/DDG
configured state + active provider). It is **visible to all users**, not
admin-only.

The admin **Integrations → Web search** block (`#web-search-block`) keeps the
provider selector (now `auto/tavily/brave/serper/ddg`), the Brave key field, and
adds a **Brave mode** select (`web` / `context`).

The blocks are self-contained so the concurrent settings-page restructure can
relocate them.

## Notes / pitfalls

- **Serper ToS:** B2B only, UK law, no SLA, no data mirroring without value-add —
  acceptable for this personal, value-added agent.
- **Brave context payloads:** the token budget is bounded (4096) and `count` is
  small so a single tool result stays compact; snippets may be structured
  (tables/code), which is fine for the model.
- **Region→language:** `langFromRegion` (Serper `hl`, Brave `search_lang`)
  defaults to `en`.
- **Cache:** bump `static/sw.js` on asset changes (currently `v9`).
