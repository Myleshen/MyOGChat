# Phase 2.4 (ext) — Pluggable web-search providers

Status: deployed (merged to `main`).

`web_search` is provider-agnostic. The model-facing tool name and its argument
schema (`{"query": "..."}`) are **unchanged**; only the backend that answers
changes. An ordered **fallback chain Tavily → Brave → DuckDuckGo** keeps search
working when a key is missing or a backend errors/rate-limits.

## Provider layer (`internal/tools/search.go`)

```go
type Result struct { Title, URL, Snippet string }

type Options struct {
    MaxResults int    // default 5, clamped to 1..20
    Region     string // DDG kl / Brave country source, e.g. "us-en"
    SafeSearch string // off | moderate | strict
}

type SearchProvider interface {
    Name() string
    Search(ctx context.Context, query string, opts Options) ([]Result, error)
}
```

Providers (each holds its own `*http.Client`, 20s timeout, and a `baseURL` field
so tests can point it at an `httptest.Server`):

| provider | `Name()` | endpoint | auth | mapping |
|---|---|---|---|---|
| Tavily | `tavily` | `POST https://api.tavily.com/search` | `Authorization: Bearer` | `results[].{title,url,content}` → `Snippet=content` |
| Brave | `brave` | `GET https://api.search.brave.com/res/v1/web/search` | `X-Subscription-Token` | `web.results[].{title,url,description}`, HTML tags stripped |
| DuckDuckGo | `ddg` | `GET https://html.duckduckgo.com/html/` | none (browser UA) | scrape `result__a` / `result__snippet`, decode `uddg` |

DuckDuckGo is a **keyless best-effort scrape** using only the standard library
(`regexp`/`strings`/`net/url` — no new dependency, no `golang.org/x/net/html`).
The `href` is a redirect (`//duckduckgo.com/l/?uddg=<encoded>`); the `uddg` query
param is decoded to recover the real URL. A non-200 response, zero parsed
results, or markup drift is treated as a provider failure (never a panic) so the
chain continues.

## Selection & fallback (`BuildSearchProviders`)

```go
type SearchConfig struct {
    Provider   string // tavily | brave | ddg | auto
    TavilyKey  string
    BraveKey   string
    MaxResults int
    Region     string
    SafeSearch string
}
func BuildSearchProviders(cfg SearchConfig) []SearchProvider
func SearchActive(cfg SearchConfig) string // which provider would answer first
```

- **Explicit** `tavily` | `brave` | `ddg` leads the chain; the other providers
  stay behind it as fallbacks.
- **`auto`** (default) → first usable of **Tavily → Brave → DuckDuckGo**.
- A keyed provider is **never constructed with an empty key**; a selected
  provider whose key is missing is skipped. DuckDuckGo needs no key, so the chain
  is never empty.
- **Fallback:** on provider error or empty results, log a warning and try the
  next. The chain is capped at `maxSearchChain = 3` providers and shares one
  overall `searchBudget = 25s` context, so a multi-provider turn cannot stall for
  `chain × 20s`.
- The tool is registered whenever **any** provider is usable (DDG alone counts).

`WebSearchTool` (`internal/tools/websearch.go`) keeps its `Name/Description/
Parameters/Run` contract and delegates to the resolved chain;
`formatSearchResults` now takes `[]Result`.

## Configuration

Environment (read in `main.go`/`loadConfig`):

| env var | meaning | default |
|---|---|---|
| `TAVILY_API_KEY` | Tavily key (existing) | — |
| `BRAVE_API_KEY` | Brave key | — |
| `MYOGCHAT_SEARCH_PROVIDER` | `tavily` \| `brave` \| `ddg` \| `auto` | `auto` |
| `MYOGCHAT_SEARCH_RESULTS` | results per query (clamped 1–20) | `5` |
| `MYOGCHAT_SEARCH_REGION` | DDG `kl` / Brave country source | `us-en` |
| `MYOGCHAT_SEARCH_SAFESEARCH` | `off` \| `moderate` \| `strict` | `moderate` |

DB settings (admin, via `GET|PATCH /api/settings`; Brave key encrypted with
`internal/secret`, mirroring the Linkwarden pattern):

- `search_provider` — provider selector (overrides the env default).
- `brave_key` — Brave API key (set/replace/clear); takes precedence over the env
  key.

`GET /api/settings` gains `brave_configured` (bool), `search_provider`
(normalized string) and `search_active` (which provider would actually be used),
alongside the existing `tavily_configured`.

## Frontend

A clearly-delimited, self-contained **web search** block in Settings →
Integrations (`static/index.html`, `<!-- web-search:start … end -->`; wired in
`static/app.js`): provider selector (auto/tavily/brave/ddg), a Brave key field
(set/replace), a **Clear key** button, and a status line showing each provider's
configured state plus the active provider. The block is self-contained so the
concurrent settings-page restructure can relocate it.
