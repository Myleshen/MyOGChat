# 5.8 — Sandbox file output (agent-created artifacts)

Status: researched, **planned** (not implemented). Design of record.
**Guiding principle: simple, fast, snappy, minimal resources.**

## Problem

`run_python` / `run_bash` run with a **tmpfs `/work`** (discarded with `--rm`)
and only return stdout/stderr, so the agent cannot hand the user a file (CSV,
TXT, PDF, XLSX, DOCX, a chart…). We want the agent to script file creation and
the user to receive the produced files.

## Minimal design

Keep it as close to the existing `generate_image` pattern as possible: a
produced-file is stored and shown as a download chip on the assistant message.

1. **Writable workspace.** Swap the `/work` tmpfs for a bind mount on a host dir
   under the service's only writable path:
   `~/.local/share/myogchat/sandbox/<run-id>` (never `/tmp` — `PrivateTmp=true`).
   Parent `0700`, per-run dir group/other-traversable so the container user
   `65534` can write. Everything else stays (`--read-only`, `--cap-drop ALL`,
   non-root, mem/cpu/pids caps, 30 s timeout). `defer os.RemoveAll` + a startup
   sweep for crash leftovers.
2. **Harvest.** After the run, walk the dir, keep **regular files only** and
   **skip symlinks** (so the container cannot link out to a host file); enforce a
   per-file size cap and a small count/total cap; sanitize the base name; sniff
   MIME. `Result.Artifacts []Artifact{Name, MIME, Data}`.
3. **Store.** A small `artifacts` table mirroring `images`
   (`id,user_id,conversation_id,name,mime,size,data,created_at`) + a JSON ref list
   on the assistant message + a retention purge in the existing janitor. Served
   by `GET /api/artifacts/{id}` (owner-scoped, **always
   `Content-Disposition: attachment`**, `nosniff`) — stored as opaque bytes, never
   extracted.
4. **Model + UI.** The sandbox tool result gains a short `--- artifacts ---` list;
   the SPA renders download chips reusing the existing `.attachment-chip` styling.

No new tool for v1 (the model already writes files inside the script). No listing
endpoint, no settings surface — YAGNI.

## The one real cost: producing PDF/XLSX/DOCX

CSV/TXT/JSON/Markdown need nothing. PDF/XLSX/DOCX/PPTX/charts need libraries, so
the sandbox **Python image** must have them preinstalled (one `deploy/` script +
Dockerfile, built once — mirroring `ocr-setup.sh`). Keep the set small
(`reportlab`, `openpyxl`, `python-docx`, `Pillow`, `matplotlib`; add others only
on request) — a big image is more Pi disk. Confirm the list before building.

## Decisions (minimal)

1. Caps: per-file 10 MB, total 25 MB, count 20.
2. The exact library set in the Python image (default above; user can trim).
3. Files the agent writes `0600` are unreadable by the app user — accept + skip
   (default umask is `0644`); no `tar` fallback unless it bites.
