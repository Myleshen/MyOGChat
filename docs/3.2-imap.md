# 3.2 — Read-only IMAP email

Connect a mailbox (Gmail / iCloud / Zoho, or any custom IMAP server) and let the
model **list folders, search, and read** mail through three tools:

- `email_folders` — list mail folders/mailboxes.
- `email_search` — search and return message summaries (uid, from, subject, date).
- `email_read` — read one message by uid (truncated text body + attachment metadata).

There is **no `email_send` and no SMTP client**. The feature is read-only by
construction (see below).

## Why app-specific passwords (not OAuth2)

- Gmail's `https://mail.google.com/` scope is restricted; an External OAuth
  consent screen in "Testing" mode issues refresh tokens that expire after 7
  days, and publishing requires Google verification. Not practical for a
  self-hosted personal app.
- iCloud has no third-party OAuth client registration for IMAP at all.
- All three providers support **app-specific passwords**, which work with plain
  SASL PLAIN over implicit TLS — pure Go, no token refresh, no browser flow.

Zoho: IMAP must be enabled in Zoho Mail settings, and **IMAP/SMTP is not
included on newly-signed-up Free plans** (paid plans only). The owner is on
Zoho **Pro**, India region (`imappro.zoho.in:993`).

## Read-only enforcement (layered)

App-specific passwords are **full-access** credentials, so scoping has to be
ours. The guardrails are layered so that no single bug can mutate a mailbox:

1. **No write path exists.** `internal/mail.Client` exposes only `Folders`,
   `Search`, `Read`, `Close`. There is no `APPEND`/`STORE`/`COPY`/`MOVE`/
   `EXPUNGE`/`CREATE`/`DELETE` method anywhere in the package.
2. **Open read-only.** Mailboxes are opened with `EXAMINE`
   (`imap.SelectOptions{ReadOnly: true}`), never `SELECT`, so opening a folder
   has no side effects.
3. **Fetch with `BODY.PEEK[]`.** Reading a message never sets `\Seen`.
4. **Transport command allowlist — the key guardrail.** Every byte the client
   writes to the socket passes through `commandFilter` (`internal/mail/allowlist.go`),
   which parses each command and rejects anything not on a small read-only set:
   `CAPABILITY, NOOP, LOGIN, AUTHENTICATE, LIST, LSUB, STATUS, EXAMINE, SELECT,
   FETCH, SEARCH, UID, IDLE, CLOSE, LOGOUT`. Additionally the `UID` sub-command
   is narrowed to `FETCH`/`SEARCH` only (so `UID STORE`/`UID COPY`/`UID MOVE`
   are rejected). The filter understands SASL continuations and IMAP literals so
   legitimate reads are not mis-flagged.
5. **Bodies are untrusted data** (prompt injection). Tool output wraps message
   content in clear `--- BEGIN MESSAGE BODY (untrusted) ---` delimiters and the
   tool result appends a note telling the model the mailbox is read-only and the
   content is data, never instructions.
6. **Outbound-only, TLS verified.** The client dials implicit TLS with
   certificate verification (never `DialInsecure` / `InsecureSkipVerify`). Only
   implicit TLS (port 993) is supported. Credentials are never returned to the
   SPA.

The tests assert the allowlist rejects `STORE`/`COPY`/`APPEND`/`EXPUNGE`/`MOVE`
(and `UID` variants), that the wire uses `EXAMINE` and `BODY.PEEK[]`, and that
no mutation command ever appears.

## Auth & connection

- One mailbox per user, stored in the `mail_accounts` table. The app password is
  encrypted at rest with `internal/secret` (AES-256-GCM) as a JSON blob
  (`{"auth_type":"password","password":"…"}`), mirroring `users.api_key_enc`.
- Per-call connect: dial → authenticate (SASL PLAIN, falling back to `LOGIN`) →
  operate → logout. Dial timeout 15 s.
- Provider presets (region-aware for Zoho):

  | id | host | port |
  |---|---|---|
  | `gmail` | `imap.gmail.com` | 993 |
  | `icloud` | `imap.mail.me.com` | 993 |
  | `zoho_in` (Pro/domain) | `imappro.zoho.in` | 993 |
  | `zoho_in_personal` | `imap.zoho.in` | 993 |
  | `zoho_com` (Pro/domain) | `imappro.zoho.com` | 993 |
  | `zoho_com_personal` | `imap.zoho.com` | 993 |
  | `zoho_eu` (Pro/domain) | `imappro.zoho.eu` | 993 |
  | `zoho_eu_personal` | `imap.zoho.eu` | 993 |
  | `custom` | user-supplied | user-supplied |

## Caps

- Text body truncated to **100 KB**; the raw message download is bounded to
  512 KB (a partial `BODY.PEEK[]` fetch), so a large attachment is never pulled
  in full.
- Search returns at most **50** summaries (default 20).
- Attachment **metadata** (filename, content type, size) is returned from
  `BODYSTRUCTURE`; attachment bytes are never fetched.

## Per-user tool registration

The email tools are registered per request **only when the caller has an enabled
mailbox** (same gating style as Linkwarden): `Server.toolRegistry(ctx, userID)`
loads the account, decrypts the password, and adds the three tools. A per-user
**"Enable email tools"** toggle (`mail_accounts.enabled`) lets a user keep the
credential but disable the tools.

## API

See `API_CONTRACT.md` §11. Per-user endpoints (all authenticated users, not
admin-only):

- `GET /api/me/mail` — connection status + provider presets (never the password).
- `PUT /api/me/mail` — connect/replace (tests the connection unless
  `skip_test:true`).
- `PATCH /api/me/mail` — `{"enabled": bool}`.
- `DELETE /api/me/mail` — disconnect (deletes the credential).
- `POST /api/me/mail/test` — test a configuration without storing it.

## Search semantics

`email_search` translates its arguments into **standard IMAP `SEARCH` keys**
(`FROM`, `TO`, `SUBJECT`, `TEXT`, `SINCE`, `BEFORE`, `UNSEEN`). Gmail's
`X-GM-RAW` syntax is intentionally **not** used: the standard keys work across
all providers and keep the wrapper free of raw command injection.

## Known gaps

- Search summaries do not include a body snippet (bodies are only fetched by
  `email_read`).
- No IDLE/push; each tool call opens a fresh connection.
- Attachments are metadata-only (no download tool in v1).
- Only implicit TLS; STARTTLS is rejected.
- A mailbox whose message text sits behind a >512 KB attachment prefix may be
  truncated in `email_read`.
