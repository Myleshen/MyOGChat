# 3.1 — Self-hosted image generation

MyOGChat can generate images from a text prompt using a **self-hosted ComfyUI**
instance (SD-Turbo, 512²) on the Proxmox GPU box. There is no external image
API: OpenCode Go exposes no image-output model, so generation runs on the LAN.

```
browser ── POST /api/images ─▶ MyOGChat (Go, Pi) ── ComfyUI native API ─▶ ComfyUI (GTX 1650 Ti)
           (stores PNG bytes, returns id)          POST /prompt, GET /history, GET /view
```

- **Backend:** ComfyUI native API at `http://comfyui.local:8188` (LXC CT 101),
  launched with `--force-fp32`. SD-Turbo 512² warm ≈ **4.5–5 s**.
- **Gate:** passed 2026-10-10 (see `docs/research/3.1-imagegen-recheck.md` and
  `docs/SCOPING.md` §3.1).

## Configuration

The backend URL + token resolve as **DB setting → env default**:

| Env | DB setting | Meaning |
|---|---|---|
| `MYOGCHAT_IMAGEGEN_URL` | `imagegen_url` | ComfyUI origin, e.g. `http://comfyui.local:8188` |
| `MYOGCHAT_IMAGEGEN_TOKEN` | `imagegen_token` | Optional bearer token (stored **encrypted** at rest) |

- The token is encrypted with `internal/secret` (AES-256-GCM) and never returned
  to the SPA — only a 4-char hint (`imagegen_token_hint`).
- Stock ComfyUI ignores the bearer token; sending it makes the client a drop-in
  for a token-guarded shim in front of ComfyUI. Keep the backend **LAN-only** —
  do **not** expose it through the Cloudflare Tunnel.
- Admins set both in **Settings → Integrations → Image generation**.

## Client (`internal/imagegen`)

Stdlib-only (`net/http`). `Client.Generate(ctx, prompt, w, h)`:

1. Builds the fixed SD-Turbo txt2img workflow (ComfyUI API format):
   `CheckpointLoaderSimple` (`sd_turbo.safetensors`) → `EmptyLatentImage` (512²)
   → two `CLIPTextEncode` (positive/negative) → `KSampler`
   (`dpmpp_2m` / `karras`, **steps 4**, **cfg 1.0**, random seed) → `VAEDecode`
   → `SaveImage` (`filename_prefix: myogchat`).
2. `POST /prompt` → `{prompt_id}`.
3. Polls `GET /history/{prompt_id}` until the entry completes; reads the first
   `outputs[<node>].images[]` reference (errors surface clearly).
4. `GET /view?filename=…&subfolder=…&type=output` → PNG bytes.

`Client.Available(ctx)` probes `GET /system_stats` (short timeout) for the
Settings "online" indicator.

**Timeouts:** one `Generate` call is bounded end-to-end (default 90 s) with a
context deadline; transport failures wrap `ErrUnreachable` so the API can return
a clear "backend unreachable" message.

## Storage (`internal/store`)

`attachments` is text-only, so images get their own table (additive migration):

```sql
CREATE TABLE IF NOT EXISTS images (
  id         TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  prompt     TEXT NOT NULL,
  model      TEXT,
  mime       TEXT NOT NULL,
  width      INTEGER NOT NULL,
  height     INTEGER NOT NULL,
  size       INTEGER NOT NULL,
  data       BLOB NOT NULL,          -- the PNG bytes
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_images_user ON images(user_id);
```

`messages` also gains an additive `images TEXT` column (JSON array of
`{id,prompt,mime,width,height,size}`) mirroring `attachments`, so a generated
image survives a history reload.

Store methods: `InsertImage`, `GetImage(id,userID)` (owner guard → `ErrNotFound`),
`DeleteImage`, `DeleteImagesOlderThan` — the last is wired into the **retention
janitor** in `main.go` next to `DeleteAttachmentsOlderThan`.

## API

| Method | Path | Notes |
|---|---|---|
| `POST` | `/api/images` | body `{prompt, size?, conversation_id?}` → `201` metadata |
| `GET` | `/api/images/{id}` | raw bytes, `Content-Type` from the row, long cache; owner-scoped `404` |
| `DELETE` | `/api/images/{id}` | `204`; owner-scoped `404` |

When `conversation_id` is supplied (and owned), the prompt + the image are also
persisted as a **user message** and an **assistant message** (with the image
reference), so the chat renders the image after a reload and the conversation is
touched/auto-titled. Without it the image is a standalone owner-scoped resource.

`GET`/`PATCH /api/settings` gain `imagegen_url`, `imagegen_configured`,
`imagegen_available` (live `system_stats` probe), and `imagegen_token_hint`
(admin only). `PATCH` accepts `imagegen_url` / `imagegen_token`; an omitted token
keeps the stored one, `""` clears it.

## UI

- **Composer:** an image button toggles a self-contained prompt bar
  (`#image-bar`); Generate posts to `/api/images` and the persisted messages are
  re-rendered.
- **Messages:** assistant messages with `images` render `<img>` thumbnails
  (click opens full size). Image-only messages show no cost footer / Retry.
- **Settings → Integrations:** an admin "Image generation" block for the URL +
  token (`#imagegen-block`).

## Testing

- `internal/imagegen`: `httptest` fake ComfyUI — workflow shape, round-trip,
  unreachable/timeout/backend-error paths, token, `Available`, URL/size parsing.
- `internal/store`: image round-trip, owner scoping, retention purge, and the
  `messages.images` round-trip.
- `internal/server`: end-to-end `POST`/`GET`/`DELETE` through the auth
  middleware (login cookie), owner scoping, conversation folding, the
  not-configured `503`, and settings encryption/precedence.

## Known gaps

- The live ComfyUI round-trip was **not** exercised here (no route from the dev
  workstation to the LXC); the client is covered by a fake server. Point
  `MYOGCHAT_IMAGEGEN_URL` at the box and click **Generate image** to smoke-test.
- BLOBs live in SQLite; fine at personal scale (a 512² PNG is a few hundred KB).
  Swapping `data BLOB` for an on-disk path keeps the same API.
- Only SD-Turbo is wired (fixed workflow). SD 1.5 / LCM would need a model
  selector.
