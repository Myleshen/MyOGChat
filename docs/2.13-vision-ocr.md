# 2.13 — Vision-model OCR (alternative OCR engine)

An alternative OCR backend that transcribes images with a **multimodal OpenCode
Go model** instead of (or as a fallback to) Docker Tesseract. It plugs into the
existing `internal/ocr.Engine` seam, so `internal/extract` and the attachment
pipeline are unchanged.

This is **opt-in**: the default engine is still Tesseract (free, local, private).
Vision OCR costs tokens and sends the image to a third party.

## Pipeline

```
POST /api/attachments (image/*)
        │
        ▼
extract.ExtractWith(name, mime, data, s.ocrFunc(ctx, u))     internal/extract
        │  image/* or a known image extension
        ▼
ocr.VisionModel.OCR(ctx, image)                              internal/ocr
        │  sniff MIME → (downscale) → data URI
        ▼
upstream.VisionOnce(ctx, VisionRequest)                      internal/upstream
        │  ONE non-streaming call, chat or responses shape
        ▼
stored in attachments.text  →  folded into the prompt (2.3)
```

`internal/extract` stays network-free: it only sees an `ocr.OCRFunc`.
`internal/ocr` owns image handling and the key binding; `internal/upstream` owns
the wire shapes. The import direction is `ocr → upstream` only.

## Wire shapes (`upstream.VisionOnce`)

One **single, non-streaming, non-tool** call — OCR must never enter the agentic
loop. Both dialects accept data URIs (`data:image/png;base64,…`).

**chat** (`deepseek-v4-flash-vision-exp`) — `content[]`, `image_url` is an object
and `detail` is nested inside it:

```json
{"model":"deepseek-v4-flash-vision-exp","stream":false,"max_tokens":2048,
 "messages":[{"role":"user","content":[
   {"type":"text","text":"…"},
   {"type":"image_url","image_url":{"url":"data:image/png;base64,…","detail":"high"}}]}]}
```

**responses** (`gpt-6-luna`) — `input[]`, `image_url` is a flat string and
`detail` is a sibling part field:

```json
{"model":"gpt-6-luna","store":false,"stream":false,"max_output_tokens":2048,
 "input":[{"role":"user","content":[
   {"type":"input_text","text":"…"},
   {"type":"input_image","image_url":"data:image/png;base64,…","detail":"high"}}]}]}
```

Parsing: chat → `choices[0].message.content`; responses → concatenate
`output[].content[].text` where the part is an `output_text`.

## The `internal/ocr` additions

- `VisionModel` — implements `Engine`; `NewVisionModel(VisionConfig{...})`.
  `OCR` sniffs the MIME, optionally downscales, builds the data URI, and calls the
  client. Errors wrap as `vision OCR: …` and become `extract.ErrOCR` at the HTTP
  layer (`400 "could not read text from the image: …"`).
- `VisionClient` — the slice of `upstream.Client` the engine needs
  (`VisionOnce(ctx, req) (string, error)`); an interface so tests never touch the
  network.
- `KeyedEngine` — an `Engine` that needs a per-request key:
  `WithKey(apiKey, sessionID) Engine` returns a bound copy.
- `FallbackEngine{Primary, Secondary}` — runs `Primary`, falling back to
  `Secondary` **only on `ErrUnavailable`** (so we never pay for vision just
  because Tesseract found no text). `WithKey` propagates to keyed children.
- `SelectEngine(mode, tess, vision)` — resolves `tesseract|vision|auto`.
- `ErrUnavailable` — Docker/image missing, or an image format the vision engine
  cannot handle (BMP/TIFF/PNM). `DockerTesseract.OCR` now returns it when the
  daemon or image is unavailable.
- `DockerAvailable(ctx, docker, image)` — a startup preflight for `auto`.

### Image handling

- **Formats:** JPEG / PNG / GIF / WebP only (both providers reject others). The
  MIME is sniffed from magic bytes; anything else (BMP/TIFF/PNM, which the
  extractor still accepts) returns `ErrUnavailable` so a fallback can retry with
  Tesseract.
- **Downscaling:** images whose longest side exceeds `MYOGCHAT_OCR_MAX_IMAGE_DIM`
  (default **2048**, `0` disables) are shrunk with a pure-Go box filter before
  being sent — no `golang.org/x/image` dependency. WebP cannot be decoded by the
  stdlib, so it is sent unchanged.
- **Prompt:** a verbatim-transcription instruction that forbids commentary and
  asks for nothing when there is no text (empty output → `extract.ErrEmpty`).

## Key binding (`Server.ocrFunc(ctx, u)`)

The vision engine is keyed, so the caller's key is resolved per request through
the normal §2.1/§2.2 order — **BYOK → group → shared server key** — and bound
with a fresh session UUID. When no key resolves, the returned `OCRFunc` errors
(→ `extract.ErrOCR`) rather than silently failing. A nil `OCRFunc` (no engine, or
the admin `ocr_enabled` setting is off) makes `internal/extract` reject images
with `ErrUnsupported`, exactly as before.

## Configuration

| Env | Default | Notes |
|---|---|---|
| `MYOGCHAT_OCR_ENGINE` | `tesseract` | `tesseract` \| `vision` \| `auto` |
| `MYOGCHAT_OCR_VISION_MODEL` | `deepseek-v4-flash-vision-exp` | registry id; must be `vision: true` |
| `MYOGCHAT_OCR_VISION_DETAIL` | `high` | `low` \| `high` \| `original` \| `auto` |
| `MYOGCHAT_OCR_VISION_MAX_TOKENS` | `2048` | output cap |
| `MYOGCHAT_OCR_VISION_TIMEOUT` | `90s` | one call; accepts `90s` or a bare number of seconds |
| `MYOGCHAT_OCR_MAX_IMAGE_DIM` | `2048` | longest side before downscaling; `0` disables |

`auto` is decided **once at startup**: a Docker preflight
(`docker info` + `docker image inspect <OCR_IMAGE>`) picks Tesseract when it is
available (with Vision as the fallback engine) and Vision otherwise. It is
predictable and never flips per request. Unknown engine/model values log a
warning and fall back to the default (`tesseract`; vision disabled).

The existing `MYOGCHAT_OCR=0` master switch still disables all OCR. The admin
`ocr_enabled` DB setting gates it per request on top.

## Model registry

`internal/models.Model` gains `vision bool` (exposed by `GET /api/models`). It is
set for the confirmed image-input models: `deepseek-v4-flash-vision-exp`,
`deepseek-v4.1-flash`, `gpt-6-luna`, `gpt-5.6-luna`, `grok-4.7`, `grok-4.6`,
`glm-5.3-flash`, `mimo-v2.6-flash`, `mimo-v2.5`, `kimi-k3`, `kimi-k2.7-code`,
`kimi-k2.6`, `space-bunny`, `longcat-2.5-preview-free`. `main.go` validates
`MYOGCHAT_OCR_VISION_MODEL` against this flag.

## Settings / API

`GET /api/settings` (§9.4) gains read-only `ocr_engine`
(`tesseract|vision|auto|none`) and `ocr_vision_available`. `ocr_enabled` /
`ocr_available` are unchanged.

## Tests

- `internal/upstream/vision_test.go` — `httptest` asserts the exact JSON for both
  dialects, the required headers, default `max_tokens`/`detail`, both response
  parsers, non-2xx → error, and empty-response handling.
- `internal/ocr/vision_test.go` — a fake `VisionClient` asserts model/dialect/
  prompt/data URI/detail/max-tokens, MIME sniffing for all four formats, trimming,
  empty-image/missing-key errors, `WithKey` binding (and that it copies), the
  unsupported-format `ErrUnavailable` path, and downscaling to the cap.
- `internal/ocr/select_test.go` — `FallbackEngine` uses Primary on success, falls
  back on `ErrUnavailable`, propagates other errors, and `WithKey` propagates;
  `SelectEngine` covers all modes.
- `internal/server/ocr_test.go` — `ocrFunc` is nil without an engine or when
  `ocr_enabled` is off; a keyed engine gets the resolved key + a session; a
  missing key errors; the settings block reports the engine/vision status.
- `internal/models/vision_test.go` — the vision flag is set on the known set.

## Pitfalls / notes

- **Privacy & cost:** the image leaves the device and spends tokens (a screenshot
  is a fraction of a cent). Tesseract stays the default.
- **Single-shot:** `VisionOnce` only — never `Stream`/`StreamAgent`.
- **`gpt-5.6-luna`** rejects images on `/chat/completions` (responses-only), so
  the dialect must match the model's registry entry.
- **base64 size:** a 10 MB upload → ~13.3 MB data URI; within both providers'
  limits but it duplicates RAM on the Pi.
- A **missing key** is reported as an OCR failure (same as any other engine
  error); the message names the key problem.
