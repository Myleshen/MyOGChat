# Phase 3.4 — Maps (keyless OpenStreetMap)

Status: implemented on branch `feat/maps` (worktree `myogchat-wt/maps`).

## Goal

Give the model geocoding, reverse geocoding, directions, and place search as
four `maps_*` tools, reusing the Phase 2.4 agentic tool loop. **OSM-only** by
owner decision: no Google Maps, no API key, no billing. The public OpenStreetMap
servers are keyless but policy-limited, so a **1 req/s limiter** and a
**result cache** are part of the feature, not an optimization.

## Provider layer (`internal/tools/maps.go`)

A `GeoProvider` interface mirroring `SearchProvider`:

```go
type LatLng struct{ Lat, Lon float64 }

type Place struct {
    Name, Address string
    Lat, Lon      float64
    Type, Source  string // source: nominatim | photon | overpass
}

type Route struct {
    DistanceMeters  float64
    DurationSeconds float64
    Mode            string
    Steps           []string
    Source          string // osrm
}

type GeoOptions struct {
    Limit   int      // default 5, clamped 1..20
    Region  string   // country code (ISO alpha-2) and/or "us-en"
    Units   string   // metric | imperial
    Mode    string   // driving | walking | cycling | transit
    Near    *LatLng  // optional bias for Places
    RadiusM int
    Type    string
}

type GeoProvider interface {
    Name() string
    Geocode(ctx, query, opts) ([]Place, error)
    Reverse(ctx, at LatLng, opts) (Place, error)
    Directions(ctx, from, to LatLng, opts) (Route, error)
    Places(ctx, query, opts) ([]Place, error)
}

type GeoConfig struct {
    Provider string // auto | osm
    Region, Units string
    Limit    int
    Cache    GeoCache // optional; nil disables caching
}
func BuildGeoProviders(cfg GeoConfig) []GeoProvider
func GeoActive(cfg GeoConfig) string // which provider would answer first
```

The chain is **never empty** (OSM needs no key) — the same invariant DuckDuckGo
provides for web search. `auto` and `osm` both resolve to the single keyless
`osmProvider`; anything else normalizes to `auto`.

### `osmProvider` (`internal/tools/maps_osm.go`)

| need | API | endpoint | notes |
|---|---|---|---|
| geocode | Nominatim | `GET {base}/search?q=…&format=jsonv2&limit=…&countrycodes=…` | `lat`/`lon` are strings; `display_name` → address |
| reverse | Nominatim | `GET {base}/reverse?lat=…&lon=…&format=jsonv2` | single object |
| directions | OSRM | `GET {base}/route/v1/{profile}/{lon,lat};{lon,lat}?overview=false&steps=true&geometries=geojson` | `driving`/`foot`/`bike`; **geojson output → no polyline decoding** |
| places | Photon | `GET {base}/api/?q=…&limit=…[&lat=&lon=&lang=]` | GeoJSON `FeatureCollection`, coordinates are `[lon,lat]` |
| places (fallback) | Overpass | `POST {base}/api/interpreter` (`data=[out:json];nwr["name"~…](around:r,lat,lon);out center N;`) | only when Photon is empty/errors **and** a `near` anchor is present |

Each provider holds its `baseURL` fields so tests can point it at an
`httptest.Server`.

**Identity headers.** Nominatim's usage policy requires a valid, app-identifying
`User-Agent` (stock library UAs are rejected); every request also sends a
`Referer`. Both point at `myogchat/1.0 (+https://github.com/Myleshen/MyOGChat)`.

**Coordinate order is centralized** (`LatLng`, `parseLatLng`, `osrmCoord`,
`formatLatLng`). OSRM takes `lon,lat`; Nominatim reverse takes `lat=`/`lon=`;
Photon GeoJSON is `[lon,lat]`. This is the #1 source of bugs, so it lives in one
place and is unit-tested.

**Transit** has no keyless routing; `maps_directions` returns a clear
"not available from the keyless OSM stack" error instead of a wrong route.

## Policy must-dos

### 1 req/s limiter (`rateLimiter`)

`osmStackLimiter` is a package-global `rateLimiter` shared by every provider
instance, so the cap holds across concurrent requests and all users (Nominatim's
policy is an absolute 1 request/second). `Wait` holds its mutex across the wait
so concurrent callers queue; it honors context cancellation. The first call
returns immediately.

### Result cache (`GeoCache` + `geo_cache`)

`GeoCache` is an interface (`GetGeoCache` / `PutGeoCache`) implemented by
`*store.Store`; the `tools` package keeps only the interface so it stays free of
storage types. Normalized results are JSON-encoded under a stable key:

- geocode → `geocode:<country>:<limit>:<lowercased query>`
- reverse → `reverse:<lat>,<lon>` (5 dp)
- directions → `route:<profile>:<from>:<to>`
- places → `places:<query>:<near>:<radius>:<type>:<limit>`

TTLs: **30 days** for geocode/reverse/places (also within Google's 30-day lat/lng
caching cap if Google is ever added), **7 days** for routes. The store's
`GetGeoCache` never returns an expired row; the retention janitor calls
`DeleteExpiredGeoCache` each hour.

## Tools (`internal/tools/maps_tools.go`)

| tool | schema | behaviour |
|---|---|---|
| `maps_geocode` | `{query*, region?, limit?}` | Nominatim search → numbered list |
| `maps_reverse` | `{lat*, lon*}` | Nominatim reverse |
| `maps_directions` | `{origin*, destination*, mode?, units?}` | `origin`/`destination` are free text or `"lat,lon"` (text is geocoded first); OSRM route + steps |
| `maps_places` | `{query*, near?, radius_m?, type?, limit?}` | Photon, Overpass fallback around `near` |

Each tool walks the provider chain (`tryGeoProviders`), skipping providers that
error or return an empty result, and formats an attributed result:

```
Route: 1.2 km · 5 min (driving)
A → B
1. Head on Main St (500 m)
2. Arrive

Source: © OpenStreetMap contributors (ODbL)
```

## Configuration

Environment (read in `main.go`/`loadConfig`):

| env var | meaning | default |
|---|---|---|
| `MYOGCHAT_MAPS_PROVIDER` | `osm` \| `auto` | `osm` |
| `MYOGCHAT_MAPS_REGION` | country code (ISO alpha-2), optional | — |
| `MYOGCHAT_MAPS_UNITS` | `metric` \| `imperial` | `metric` |
| `MYOGCHAT_MAPS_LIMIT` | results per query (clamped 1–20) | `5` |

DB settings (admin, via `GET|PATCH /api/settings`; DB overrides env when set):

- `maps_provider` — provider selector (`osm`|`auto`; unknown → `auto`).
- `maps_region` — optional country-code bias (Nominatim `countrycodes`, Photon
  `lang` when given as `us-en`).
- `maps_units` — `metric`|`imperial`.

`GET /api/settings` gains `maps_provider`, `maps_region`, `maps_units`, and
`maps_active`. The tools reuse the global `tools_enabled` gate; no separate
on/off.

## Frontend

A clearly-delimited, self-contained **maps** block in Settings → Integrations
(`static/index.html`, `<!-- maps:start … end -->`; wired in `static/app.js`):
provider (fixed to OpenStreetMap), an optional region field, a units selector,
a status line, and a **Save** button. It is admin-only, like the other
Integrations controls, and is self-contained so the settings page can relocate
it. `static/sw.js` cache bumped to `v9`.

## Known gaps / caveats

- The public Nominatim/OSRM/Photon/Overpass instances are **best-effort** (no
  SLA; the OSRM demo server is explicitly not for production). The fallback
  chain, cache, and limiter keep usage inside the acceptable-use envelope, but a
  down server still surfaces as a clear error. Self-hosting was evaluated and
  rejected as impractical on the Pi 4B (see `docs/research/3.4-maps.md`).
- Overpass's "pause 30 s on 429" guidance is **not** implemented as an automatic
  backoff (it would stall a chat turn); the limiter + cache are the mitigation.
- No autocomplete (Nominatim forbids it); `maps_places` is a discrete search, not
  a typeahead.
- Google Maps was dropped by owner decision; the `GeoProvider` layer leaves room
  for a future keyed provider without touching the tools.
