# 2.3 — Files & PDF attachments

Users can attach files to a message. The server extracts plain text, stores it,
and folds it into the model request inside a character budget. **Images** are
handled by OCR in [2.5](2.5-ocr.md) (Tesseract in a Docker container); this
document covers the text/PDF pipeline that OCR reuses.

## Schema (additive)

```sql
CREATE TABLE IF NOT EXISTS attachments (
  id         TEXT PRIMARY KEY,
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  name       TEXT NOT NULL,
  mime       TEXT,
  size       INTEGER NOT NULL,
  text       TEXT NOT NULL,
  created_at INTEGER NOT NULL
);
CREATE INDEX IF NOT EXISTS idx_attachments_user ON attachments(user_id);
```

The `attachments` table is created by the base schema; `internal/store.migrate()`
also adds one supporting column to legacy databases:

```sql
ALTER TABLE messages ADD COLUMN attachments TEXT;  -- JSON array of {id,name,mime,size}
```

`messages.attachments` persists only the **display metadata** of the files sent
with a user message, so the UI can keep showing "N file(s) attached" after a
reload. The extracted text stays in `attachments.text` and is reloaded by id
when a message is sent (and re-folded on regenerate).

## Endpoints

All require a session and are scoped to the caller; another user's id returns
`404`.

| Method | Path | Body | Response |
|---|---|---|---|
| `POST` | `/api/attachments` | `multipart/form-data`, field `file`, ≤ 10 MB | `201 {id,name,mime,size,chars}` |
| `GET` | `/api/attachments/{id}` | — | `200 {id,name,mime,size,chars,created_at}` |
| `DELETE` | `/api/attachments/{id}` | — | `204` |

`POST /api/conversations/{id}/messages` gains an optional
`attachment_ids: []string`. Every id must exist and belong to the caller (else
`400 unknown attachment`); at most **20** files are folded per message.

## Extraction (`internal/extract`)

- **UTF-8 text / code / JSON / CSV / Markdown** — used as-is after validating
  UTF-8 and stripping NUL bytes. Detection uses MIME (`text/*`,
  `application/json`, …), the filename extension, or a "valid UTF-8, no NUL"
  probe when the browser sends no usable type.
- **PDF** — parsed with `github.com/ledongthuc/pdf`.
- **Images** — OCR'd via an injected `ocr.OCRFunc` (2.5); with OCR disabled they
  are rejected with `ErrUnsupported`.
- Anything else — rejected as an unsupported file type.

Limits:

| Limit | Value | Where |
|---|---|---|
| Per-file upload size | 10 MB | `maxAttachmentBytes` (server) |
| Extracted text stored per file | 1,000,000 chars (runes) + `TruncationMarker` | `extract.MaxTextChars` |
| Files per message | 20 | `maxAttachmentsPerMessage` |
| Attached-text budget per request | 200,000 chars total | `maxAttachedChars` (`foldAttachments`) |

Over-budget text is cut and a clear marker is appended
(`[... attachment truncated to fit the context budget ...]`); attachments that
do not fit at all are noted as omitted.

## PDF library decision

**`github.com/ledongthuc/pdf`** (BSD-3-Clause, fork of `rsc/pdf`).

- **Pure Go, CGO-free** — builds with `CGO_ENABLED=0` and cross-compiles to
  `linux/arm64` (verified). The alternative (`pdftotext`) would require a binary
  on the Pi, which the deployment does not manage.
- Single, small dependency; no transitive deps added (`go.mod` lists only the
  module itself).
- Used via `pdf.NewReader(bytes.NewReader(data), size)` + `r.GetPlainText()`;
  the call is guarded with `recover` because the parser can panic on malformed
  input.

This is the one approved extra dependency beyond `modernc.org/sqlite`.

## Prompt folding

`foldAttachments` renders the attachments as a leading context block:

```
The user attached the following file(s). Treat their contents as context for the request.

### report.pdf
<text…>
```

- **chat dialect** — prepended as a leading `system` message (before the project
  instructions system message).
- **responses dialect** — prepended as a leading `system` input item; project
  instructions continue to use the top-level `instructions` field.

Implemented in `upstream.Params.Context` (`internal/upstream/upstream.go`).

## Frontend (`static/`)

- A paperclip button in the composer opens a file picker (`multiple`).
- Each selected file uploads immediately; removable chips (name + size) render
  above the composer while uploading/after upload. Removing a pending chip
  `DELETE`s the server copy.
- Sending includes `attachment_ids`; the user bubble shows "N file(s) attached".
- Sending is disabled while an upload is in flight. On a fatal send error the
  chips are restored so the user can retry.
- `sw.js` cache bumped to `myogchat-shell-v7`.

## Retention

The hourly janitor also purges attachments older than the retention window
(`DeleteAttachmentsOlderThan`). Regenerate tolerates a purged attachment by
skipping it.
