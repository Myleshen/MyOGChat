# Phase 2.8 — URL summarization + Linkwarden

Status: implemented. Linkwarden is **per-user** (each user connects their own
instance); see `API_CONTRACT.md` §17.
Depends on the tool loop from `2.4-tools.md`.

## URL summarization

There is no separate "summarize" endpoint: the `fetch_url` tool (Phase 2.4) is
the primitive. When the user pastes a URL or asks about a page, the model calls
`fetch_url`, the server returns the readable text, and the model summarizes it.

`fetch_url`:

1. Only `http`/`https` URLs with a host.
2. Fetches with a browser-ish User-Agent, capped at 2 MB.
3. HTML → readable text via a dependency-free extractor (`HTMLToText`):
   comments and `script`/`style`/`noscript`/`template`/`svg`/`head`/`iframe`/
   `object`/`embed` contents dropped, block elements become line breaks, tags
   stripped, entities decoded, whitespace collapsed. `<title>` is returned
   separately (`ExtractTitle`).
4. Truncated to 12000 characters before it is handed to the model.
5. SSRF-guarded: the transport refuses to dial non-public IPs (loopback,
   private, link-local, multicast, CGNAT) at connection time.

## Linkwarden (per-user)

Each user connects **their own** self-hosted [Linkwarden](https://linkwarden.app)
instance to search saved links and save new ones from a chat. The model queries
the **caller's** instance; there is no shared/global instance any more.

### Storage & secrets

Per-user columns on `users` (additive migration, mirrors `serper_key_enc`):

| column | value |
|---|---|
| `linkwarden_url` | instance origin, e.g. `https://links.example.com` |
| `linkwarden_token_enc` | **encrypted** API token (AES-256-GCM via `internal/secret`, reusing the §2.1 `encryption_key`) |

The URL is normalized (`NormalizeBaseURL`): a missing scheme defaults to
`https://`, trailing `/` and a trailing `/api/v1` are stripped.

An **optional server-wide fallback** exists for single-user/self-hosted
deployments: the env vars `LINKWARDEN_URL` + `LINKWARDEN_TOKEN` (both must be
set) are used only when the caller has not stored their own instance. The old
admin-global `linkwarden_url` / `linkwarden_token` DB settings are removed.

### API client (`internal/tools/linkwarden.go`)

- Auth: `Authorization: Bearer <token>` (a Linkwarden API token created from the
  instance's user settings).
- Search: `GET {base}/api/v1/search?searchQueryString=<q>`. Accepts both
  documented response shapes: `{"data":{"links":[…]}}` and `{"data":[…]}`.
- Save: `POST {base}/api/v1/links` with `{"url":…,"name"?:…}`. Success is
  `{"response":{…link…}}`; an error is `{"response":"<message>"}` and is surfaced
  to the model as the tool error.
- `Check(ctx)` performs the lightweight authenticated request used to validate a
  user's URL + token on save.

### Tools

| tool | description |
|---|---|
| `linkwarden_search(query)` | search saved bookmarks; returns `- name — url` lines |
| `linkwarden_save(url, title?)` | save a URL; returns `Saved to Linkwarden: …` |

Both are registered per request from the **caller's** config (their URL + a
decryptable token, else the env fallback) — exactly like the email/calendar
tools.

## Per-user API (all users)

- `GET /api/me/linkwarden` → `{"configured", "url", "token_hint"}`.
- `PUT /api/me/linkwarden` `{"url", "token"?}` → validates (lightweight request),
  normalizes, encrypts, stores. `token` omitted/empty keeps the stored token.
- `DELETE /api/me/linkwarden` → `204` (clears the caller's own instance).

The admin `GET`/`PATCH /api/settings` no longer carries Linkwarden fields (only
the tools toggle + Tavily/search status remain there).

## CLI

Operators can set per-user secrets directly in the DB without a login:

```sh
myogchat user setkey --username <name> [--serper <key>] \
  [--linkwarden-url <url>] [--linkwarden-token <token>]
```

Secrets are encrypted with `internal/secret` using the DB `encryption_key`
setting (created on first use, as the server does). An empty value clears that
field; an omitted flag leaves it untouched. Output is redacted — the secret is
never printed.

## Frontend

Settings → **Linkwarden** (a self-contained, per-user section visible to all
users): Instance URL + API token fields with **Save** and **Disconnect**. The
token is never echoed back — only `token_hint` (last 4 chars) is shown. The admin
Integrations section keeps the tools toggle and the web-search block.
