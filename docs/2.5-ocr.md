# 2.5 — OCR for images

Uploaded **images** are OCR'd to text and folded into the model request exactly
like any other attachment (2.3). Text/code and PDF handling is unchanged.

OCR runs **Tesseract inside a throwaway, hardened Docker container** rather than
on the host: the Pi has no `tesseract` and `sudo` needs a password, so nothing is
installed system-wide. The image bytes go in over **stdin** and the recognized
text comes back on **stdout**.

## Pipeline

```
POST /api/attachments (image/*)
        │
        ▼
extract.ExtractWith(name, mime, data, ocrFunc)   internal/extract
        │  image/* or a known image extension
        ▼
ocr.DockerTesseract.OCR(ctx, image)              internal/ocr
        │  docker run … tesseract stdin stdout -l eng
        ▼
stored in attachments.text  →  folded into the prompt (2.3)
```

`internal/extract` stays Docker-free: it takes an injected `ocr.OCRFunc`
(`func([]byte) (string, error)`). `internal/ocr` owns the container mechanics.
`internal/server` bridges the two and applies the enable/disable rules.

## The `internal/ocr` package

- `Engine` — `OCR(ctx, image) (string, error)`.
- `OCRFunc` — `func(image []byte) (string, error)`; the extractor's seam.
  `ocr.Func(ctx, engine)` adapts an `Engine` to an `OCRFunc`.
- `DockerTesseract` — the implementation; `NewDockerTesseract(Config{...})`.
- `CommandRunner` — injectable executor (`ExecRunner` in production) so tests
  assert the argv, stdin, timeout, and cleanup without a Docker daemon.

### Container hardening

`docker run` flags (mirroring the sandbox design):

```
--rm --name myogchat-ocr-<random>
--network none --memory 256m --cpus 1 --pids-limit 64
--read-only --tmpfs /tmp:rw,size=32m
--cap-drop ALL --security-opt no-new-privileges --user 65534:65534
-i <image> tesseract stdin stdout -l <langs>
```

- `-i` keeps stdin open so the image can be piped in.
- `--rm` removes the container when it exits normally.
- A **30 s timeout** (`MYOGCHAT_OCR_TIMEOUT`) bounds one run. If it fires, the
  CLI is killed but the container may still be running, so the engine runs an
  explicit `docker rm -f <name>` cleanup (the unique `--name` makes this safe).

## Extraction behavior

| Situation | Result |
|---|---|
| Image + OCR enabled | recognized text, whitespace-trimmed, capped at `extract.MaxTextChars` |
| Image + OCR disabled/unavailable (nil `OCRFunc`) | `ErrUnsupported` (`images require OCR, which is disabled`) |
| OCR engine failure (docker missing, timeout, …) | `ErrOCR` (`could not read text from the image: …`) |
| Image with no recognizable text | `ErrEmpty` |

Images are detected by MIME (`image/*`) or, when the browser sends a generic
type, by extension (`.png .jpg .jpeg .gif .bmp .tif .tiff .webp .pbm .pgm .ppm
.pnm`). The OCR output reuses `extract.MaxTextChars` / `TruncationMarker`, and
the normal per-message attachment budget still applies when folding.

## Configuration

| Env | Default | Notes |
|---|---|---|
| `MYOGCHAT_OCR` | `1` | master switch; `0` builds no engine (images always `ErrUnsupported`) |
| `MYOGCHAT_OCR_IMAGE` | `myogchat-ocr` | Docker image tag (see `deploy/ocr/`) |
| `MYOGCHAT_OCR_LANGS` | `eng` | Tesseract language list, e.g. `eng+deu` |
| `MYOGCHAT_DOCKER` | `/usr/bin/docker` | docker binary path |
| `MYOGCHAT_OCR_TIMEOUT` | `30s` | one run; accepts `30s` or a bare number of seconds |

A DB-backed global setting **`ocr_enabled`** (default `true`) gates OCR on top of
`MYOGCHAT_OCR`; admins toggle it in Settings. It is surfaced by
`GET /api/settings` and set by `PATCH /api/settings` (see `API_CONTRACT.md` §9.4).

## Docker image

`deploy/ocr/Dockerfile` — pinned `alpine:3.20` + tesseract:

```dockerfile
FROM alpine:3.20
RUN apk add --no-cache tesseract-ocr tesseract-ocr-data-eng
```

Package names verified against the Alpine **v3.20 community** repo (aarch64 and
x86_64): `tesseract-ocr` (5.3.4-r0) and `tesseract-ocr-data-eng` (5.3.4-r0).

Build it once on the Pi (Docker must be installed and the service user in the
`docker` group):

```sh
bash deploy/ocr-setup.sh          # builds & tags myogchat-ocr, prints tesseract --version
```

Then restart the service. The server needs no tesseract on the host.

## Settings UI

A **clearly delimited, self-contained** block in the settings modal
(`#ocr-section` in `index.html`, marked with `<!-- ===== Image OCR (feature 2.5)
… ===== -->`), visible to admins only, with an **Enable image OCR** toggle and a
status line (`Image OCR is on/off`, or `OCR engine not configured on the
server.`). It is intentionally easy to relocate when the settings modal is
restructured into a page (2.9). `static/sw.js` cache bumped to
`myogchat-shell-v8`.

## Tests

- `internal/ocr/ocr_test.go` — a fake `CommandRunner` asserts the full argv, the
  stdin bytes, output trimming, the configured languages, timeout +
  `docker rm -f` cleanup, and that a fast failure does **not** clean up. An
  opt-in live smoke test (`MYOGCHAT_OCR_LIVE=1`) builds nothing itself but skips
  unless Docker, the image, and ImageMagick are present.
- `internal/extract/extract_test.go` — an injected OCR func proves images now
  yield text (by MIME and by extension); a nil OCR func still yields
  `ErrUnsupported`; an OCR error yields `ErrOCR`; blank output yields `ErrEmpty`.
