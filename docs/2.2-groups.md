# Phase 2.2 — Groups & shared keys

Adds **groups**: a group owner can share their OpenCode Go key with the group's
members. This extends the key resolution order from §2.1.

## Schema (additive)

```sql
CREATE TABLE IF NOT EXISTS groups (
  id         TEXT PRIMARY KEY,
  name       TEXT NOT NULL,
  owner_id   TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  share_key  INTEGER NOT NULL DEFAULT 1,
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
CREATE TABLE IF NOT EXISTS group_members (
  group_id   TEXT NOT NULL REFERENCES groups(id) ON DELETE CASCADE,
  user_id    TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  role       TEXT NOT NULL DEFAULT 'member',
  created_at INTEGER NOT NULL,
  PRIMARY KEY (group_id, user_id)
);
CREATE INDEX IF NOT EXISTS idx_group_members_user ON group_members(user_id);
CREATE INDEX IF NOT EXISTS idx_groups_owner ON groups(owner_id);
```

Both tables ship in the base schema (`CREATE TABLE IF NOT EXISTS`), so existing
databases gain them on the next open without data loss. Deleting a group or a
user cascades memberships; deleting a group owner cascades the group.

The owner is **not** inserted into `group_members`; ownership is tracked by
`groups.owner_id`. The owner's own key is already preferred during resolution,
so no self-membership is needed.

## Key resolution order (§2.1 + §2.2)

For every chat/regenerate request:

1. **Own key** — the caller's stored (encrypted) key.
2. **Group key** — the caller's groups where `share_key = 1` and the owner has a
   stored key, in `created_at ASC` order; the first one that yields a readable
   key wins.
3. **Server key** — `OPENCODE_API_KEY`, only when `share_server_key` is on.
4. Otherwise a clear error: `no OpenCode Go API key configured — add one in Settings`.

## Endpoints (all require a session)

Group JSON shape:

```json
{
  "id": "uuid",
  "name": "Team",
  "owner_id": "uuid",
  "share_key": true,
  "created_at": 1700000000000,
  "updated_at": 1700000000000,
  "is_owner": true,
  "members": [
    {"user_id": "uuid", "username": "alice", "email": "alice@example.com", "role": "member"}
  ]
}
```

- `GET /api/groups` → array of groups the caller owns or belongs to, each with
  the shape above (`is_owner` relative to the caller; `members` populated).
- `POST /api/groups` body `{"name": "…", "share_key"?: bool}` → `201` group.
  `name` is required, trimmed, ≤ 120 chars. `share_key` defaults to `true`.
  The caller becomes the owner.
- `PATCH /api/groups/{id}` body `{"name"?: string, "share_key"?: bool}` →
  `200` updated group. **Owner only** (`403` otherwise, `404` if unknown).
- `DELETE /api/groups/{id}` → `204`. **Owner only**.
- `POST /api/groups/{id}/members` body `{"identifier": "username-or-email"}` →
  `201` updated group. **Owner only**. `404` when the user is unknown, `409`
  when already a member, `400` when the identifier is the owner.
- `DELETE /api/groups/{id}/members/{userId}` → `204`. **Owner or admin**
  (`403` otherwise), `404` when the group or membership is unknown.

Errors use the standard `{"error": "…"}` body.

## `GET /api/me/key` additions

The response gains:

- `group_key_available` (bool) — a usable group key exists for the caller.
- `using_group_key` (bool) — the caller has no own key and a group key applies.
- `group_name` (string) — the name of the group that would supply the key
  (empty when none).

Existing fields (`has_key`, `key_hint`, `server_key_present`,
`shared_key_available`, `using_shared_key`) are unchanged; `using_shared_key` is
now only true when neither an own nor a group key applies.

## Frontend

Settings → **Groups**:

- Lists the caller's groups with an `owner` badge and a `sharing key` /
  `not sharing` badge.
- **Create group**: name + "Share my key with this group" toggle.
- Owners can rename, delete, toggle sharing, add members (username or email),
  and remove members. Admins can remove members from any group.
- The OpenCode Go key status shows `Using <group>'s shared key.` when a group key
  is in use.

`sw.js` cache version is bumped so clients pick up the new shell.
