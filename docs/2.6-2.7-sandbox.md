# 2.6 Python sandbox + 2.7 Bash sandbox

Give the model two tools — **`run_bash`** and **`run_python`** — that execute
model-generated code inside a hardened, resource-limited, **ephemeral** Docker
container and return stdout/stderr.

- **`run_bash`** — runs the script with `bash -s` (image `bash:5.3`).
- **`run_python`** — runs the script with `python -` (image `python:3.14-slim`).

The sandbox is **enabled by default** and **has outbound network access** (the
owner's explicit choice). It is hardened as much as possible: no inbound path,
no host access, strict resource caps.

## Engine

- **Docker**, one **ephemeral** container per call (`docker run --rm`). Nothing
  persists between calls — every call is a brand-new container with a read-only
  root filesystem.
- The code is fed to the interpreter over **stdin**; it is never interpolated
  into the command line (no shell-injection surface).
- Images are configurable; verified tags: `bash:5.3`, `python:3.14-slim`
  (both publish `linux/arm64/v8`, so they run on the Pi 4B).
- `docker run` is called with `--pull=never`, so a missing image fails fast with
  a clear, actionable error instead of silently pulling mid-call.

## Hardening applied to every call

| Flag | Purpose |
|---|---|
| `--rm` | ephemeral container |
| `--name myogchat-sbx-<rand>` + `--label myogchat-sandbox=1` | unique name + cleanup label |
| `--network myogchat-sbx` | dedicated **user-defined bridge** (no published ports → **no inbound path**) |
| `--cap-drop ALL` | drop every Linux capability |
| `--security-opt no-new-privileges` | no setuid/privilege escalation |
| `--user 65534:65534` | non-root (`nobody`), with `HOME=/work`, `TMPDIR=/tmp` |
| `--read-only` | read-only root filesystem |
| `--tmpfs /work:rw,exec,size=64m` | writable working dir (exec allowed) |
| `--tmpfs /tmp:rw,size=16m` | small writable `/tmp` |
| `--workdir /work` | scripts run in the writable tmpfs |
| `--memory 256m --memory-swap 256m` | hard RAM cap (no swap) |
| `--cpus 1` | one CPU |
| `--pids-limit 128` | fork-bomb guard |
| `--ulimit nofile=256:256` | file-descriptor cap |
| `--stop-timeout 2` | fast SIGKILL on stop |

The Docker socket (and any other host path) is **never** mounted into the
container.

### Timeout and cleanup

Each call is bounded by a wall-clock timeout (`MYOGCHAT_SANDBOX_TIMEOUT`,
default **30 s**) enforced with `exec.CommandContext`. On timeout the runner
explicitly runs `docker rm -f <name>` (with a fresh context) so a container can
never leak, and returns any partial output plus a "timed out" note to the model.
A cancelled request (client disconnect) triggers the same cleanup.

### Egress hardening

`deploy/sandbox-setup.sh` does two things:

1. **No sudo:** creates the `myogchat-sbx` network and pulls both images.
2. **`sudo deploy/sandbox-setup.sh --harden`:** adds iptables rules so the
   sandbox can reach the **public internet only**:
   - `DOCKER-USER`: `DROP` sandbox egress to RFC1918 (`10/8`, `172.16/12`,
     `192.168/16`), link-local (`169.254/16`), loopback (`127/8`), CGNAT
     (`100.64/10`), multicast and broadcast — i.e. other LAN hosts.
   - `INPUT`: `DROP` sandbox traffic to the host's own addresses (LAN IP and
     Docker bridge gateways). Container→host traffic is delivered locally and
     bypasses `DOCKER-USER`, so without this the sandbox could still reach the
     app, SSH, DNS and other host services.

> **Without the sudo step the container can still reach your LAN.** The owner
> chose outbound network access for the sandbox, so this is opt-in hardening.

## Configuration (env)

| Var | Default | Notes |
|---|---|---|
| `MYOGCHAT_SANDBOX` | `1` | hard kill switch; `0`/`false`/`off`/`no` disables the tools entirely |
| `MYOGCHAT_DOCKER` | `/usr/bin/docker` | docker CLI path (falls back to `exec.LookPath`) |
| `MYOGCHAT_SANDBOX_NETWORK` | `myogchat-sbx` | dedicated bridge network name |
| `MYOGCHAT_SANDBOX_IMAGE_BASH` | `bash:5.3` | image for `run_bash` |
| `MYOGCHAT_SANDBOX_IMAGE_PYTHON` | `python:3.14-slim` | image for `run_python` |
| `MYOGCHAT_SANDBOX_TIMEOUT` | `30` | per-call timeout, seconds |
| `MYOGCHAT_SANDBOX_MEMORY` | `256m` | memory (and memory-swap) limit |
| `MYOGCHAT_SANDBOX_CPUS` | `1` | CPU limit |
| `MYOGCHAT_SANDBOX_MAX_OUTPUT` | `100000` | max characters of stdout+stderr returned |

## Admin setting

- DB setting `sandbox_enabled` (default **true**), surfaced through
  `GET`/`PATCH /api/settings` and toggleable by admins in **Settings → Code
  sandbox**.
- `sandbox_available` reports whether Docker is reachable (and the env kill
  switch is on); the tools are registered per request only when
  `tools_enabled` **and** `sandbox_enabled` **and** Docker is reachable.
- If the images are missing, the tool returns a clear error pointing at
  `deploy/sandbox-setup.sh`.

## Package layout

- `internal/sandbox` — the `Runner` (injectable command executor so it is
  unit-testable without Docker): `Run(ctx, Spec) (Result, error)`, argv
  construction, timeout/cleanup, output capture + truncation (~100 k chars),
  and error mapping.
- `internal/tools` — `run_bash` / `run_python` `Tool` implementations that call
  the runner.

## Tests

- `internal/sandbox` unit tests inject a fake executor and assert the exact
  hardened `docker run` argv, stdin handling, timeout → `docker rm -f` cleanup,
  truncation, and error mapping. `live_test.go` adds live Docker smoke tests
  (skipped when Docker is absent / images are not pulled).
- `internal/tools` unit tests cover arg decoding, output shaping, and error
  paths.

## Setup

```sh
# once, on the host (no sudo):
bash deploy/sandbox-setup.sh
# optional LAN-egress hardening (sudo):
sudo MYOGCHAT_SANDBOX_NETWORK=myogchat-sbx bash deploy/sandbox-setup.sh --harden
```
