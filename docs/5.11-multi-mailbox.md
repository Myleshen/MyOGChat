# 5.11 — Multiple mailboxes per user

Status: researched, **planned** (not implemented). Design of record.
**Guiding principle: simple, fast, snappy, minimal resources.**

## Problem

Email is currently **one mailbox per user** — `mail_accounts` has `user_id` as its
PRIMARY KEY, the endpoints are singular (`/api/me/mail`), and the tools implicitly
use "the" account. The user needs multiple mailboxes per user.

## Minimal design

1. **Schema (additive, lossless rebuild).** SQLite cannot alter a PRIMARY KEY, so
   rebuild the table once (guarded by "does `id` exist?"), copying the existing
   row verbatim (ciphertext included) and marking it `is_default = 1`:

   ```sql
   mail_accounts(
     id TEXT PRIMARY KEY,
     user_id TEXT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
     label TEXT NOT NULL DEFAULT '',
     provider, email, imap_host, imap_port, imap_tls, enabled,
     is_default INTEGER NOT NULL DEFAULT 0,
     secret_enc, created_at, updated_at
   );
   CREATE INDEX idx_mail_accounts_user ON mail_accounts(user_id);
   CREATE UNIQUE INDEX idx_mail_accounts_default
     ON mail_accounts(user_id) WHERE is_default = 1;
   ```

   Fresh installs get this shape from the `schema` const (rebuild skipped). The id
   is generated in SQL: `lower(hex(randomblob(16)))` — core SQLite, no new dep.

2. **Endpoints** (canonical): `GET/POST /api/me/mail/accounts`,
   `PATCH/DELETE /api/me/mail/accounts/{id}`,
   `POST /api/me/mail/accounts/{id}/test`; keep `POST /api/me/mail/test`
   (stateless) and the singular `GET/PUT/PATCH/DELETE /api/me/mail` as **thin
   aliases to the default** (cheap back-compat while clients update).
   `secret_enc` is never serialized.

3. **Tools.** The connector takes an optional account ref
   (`func(ctx, account) (EmailConn, error)`, `""` = default) resolved at call
   time; `email_folders`/`email_search`/`email_read` gain an optional
   `account` param; a tiny **`email_accounts`** tool lists the user's mailboxes
   (label — email, id, default) so the model can choose. Registered when ≥1
   enabled account exists.

4. **SPA.** Replace the single form with an accounts list (add / edit / test /
   remove / set-default / enable). Reuse the existing form fields; add `label`.
   Per-account `enabled` replaces the single per-user toggle.

5. **`email_digest` (5.9)** spans **all enabled accounts** by default, grouped by
   mailbox; `account:` narrows to one. Bare `email_search`/`email_read` stay on the
   **default** account (precision). Document that asymmetry.

## Decisions (minimal)

1. `email_digest`: all enabled accounts (recommended) vs default only.
2. Singular endpoints: keep as default aliases (recommended) vs remove.
3. `account` ref: id + case-insensitive label (recommended) vs id-only.
4. Cap accounts per user at 10 (guard against runaway rows).

## Notes

- One global `encryption_key` encrypts every account's `secret_enc` (as today);
  no key change needed. Cross-user access collapses to 404.
- Read-only IMAP guarantees are per-connection and unaffected.
