# Phase 2.9 — Full settings page (not a popup)

Promotes the old `#settings-modal` dialog to a dedicated, mobile-first **page**
at the hash route **`#/settings`**. Frontend-only: no new API endpoints, no build
step, no framework — still the embedded vanilla-JS PWA.

## What changed

| Before | After |
|---|---|
| `#settings-modal` (centered `.modal-card`, `role="dialog"`) | `#settings-page` (full-screen, scrollable page) |
| Gear opened the modal via `openModal()` | Gear navigates to `#/settings` |
| Closed via ✕ / backdrop / Esc | Back affordance + Esc + browser/Android back button |
| No URL | Deep-linkable / reload-safe route `#/settings` |

There is now **one** settings surface — the modal was removed entirely.

## Routing

`static/app.js` gained a small hash router (there was none before):

- `SETTINGS_HASH = "#/settings"`.
- `navigateToSettings()` sets `location.hash` (pushes a history entry) and marks
  the navigation as in-app (`settingsPushed = true`).
- `applyRoute()` shows the page when `state.user && location.hash === "#/settings"`,
  otherwise hides it. It runs on `hashchange` and after `enterApp()` (so a reload
  or deep link on `#/settings` opens the page).
- `leaveSettings()` uses `history.back()` when settings was opened from inside
  the app, or `history.replaceState()` to clear the hash when settings was the
  entry point (deep link / reload) — never stacking a dead history entry.

The browser and Android back buttons therefore return to the previous view with
no extra JS, because they drive `hashchange`.

## Sections

Each section is a `<section class="settings-section">` with an uppercase
heading. Element ids are unchanged from the old modal, so all existing behavior
and tests keep working.

1. **Account** — username + email from `GET /api/auth/me` (already loaded as
   `state.user`), plus a **Log out** button (`POST /api/auth/logout`). No
   change-password endpoint exists, so none is offered.
2. **Appearance** — theme (`system`/`light`/`dark`), thinking display,
   show-tokens/sec, Enter-to-send. These are the browser-local `myogchat.*`
   preferences (contract §8.8) and behave exactly as before.
3. **OpenCode Go key** — existing `#key-section`: status, add/replace/remove,
   and the admin **share the server key with users** toggle.
4. **Groups** — existing `#groups-section`: list, create, members, share-key.
5. **Integrations** (admin) — existing `#integrations-section`: tools toggle,
   Tavily status, Linkwarden URL/token.
6. **Users** (admin) — existing `#users-section`: pending count, allow
   registration, user list/actions, add user.
7. **About** — app name + version (`APP_VERSION` in `app.js`).

## Mobile / PWA

- `.settings-page` is `position: fixed` using the shared visual-viewport
  variables (`--app-top` / `--app-h`) that the composer already relies on, so the
  on-screen keyboard resizes the page instead of breaking layout.
- `.settings-body` is the independent scroll container
  (`overflow-y: auto; overscroll-behavior: contain`).
- Layout is single-column, `box-sizing: border-box`, inputs `width: 100%`, and
  long values `overflow-wrap: anywhere` — no horizontal overflow at 412×915
  (Pixel 7). On desktop the section column is centered at `max-width: 680px`.
- `static/sw.js` cache version bumped **v7 → v8** so clients pick up the new
  shell.
