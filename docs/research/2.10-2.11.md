### Server collection (`internal/server/chat.go`)

pair becomes one persisted entry:
```go
// mergeToolEvent folds one upstream tool activity into the persisted list,
// mirroring the SPA: "running" starts an entry; a terminal event closes the
// most recent matching running entry, else appends.
func mergeToolEvent(list []store.ToolActivity, t *upstream.ToolActivity) []store.ToolActivity {
	if t.Status == upstream.ToolRunning {
		return append(list, store.ToolActivity{Name: t.Name, Status: t.Status})
	}
	for i := len(list) - 1; i >= 0; i-- {
		if list[i].Name == t.Name && list[i].Status == upstream.ToolRunning {
			list[i].Status, list[i].Summary = t.Status, t.Summary
			return list
		}
	}
	return append(list, store.ToolActivity{Name: t.Name, Status: t.Status, Summary: t.Summary})
}
```
Set `Tools: tools` on `asstMsg` (`chat.go:283`) before `InsertMessage`.

## 2.11 Usage & quota accounting

### Data model (no new table)
Usage = aggregate over assistant `messages` joined to `conversations` for owner
scoping:
```sql
SELECT ... FROM messages m JOIN conversations c ON c.id = m.conversation_id
WHERE c.user_id = ? AND m.role = 'assistant' AND m.created_at >= ?
```
`created_at` is unix **millis**; group days with
`strftime('%Y-%m-%d', m.created_at/1000, 'unixepoch')`. Cutoff `0` = all time.

### Store aggregates (`internal/store/store.go`, new `---------- usage (2.11) ----------`)
```go
type UsageTotals struct { // + json tags
	PromptTokens, CompletionTokens, CachedTokens, ReasoningTokens, CostMicros, Messages int64
}
type UsageRow struct { // one by-day / by-model bucket
	Day, Model string // json:"day,omitempty" / json:"model,omitempty"
	UsageTotals
}
type UserUsage struct { UserID, Username string; UsageTotals } // admin view

func (s *Store) UserUsageTotals(ctx context.Context, userID string, cutoff int64) (UsageTotals, error)
func (s *Store) UserUsageByDay(ctx context.Context, userID string, cutoff int64) ([]UsageRow, error)
func (s *Store) UserUsageByModel(ctx context.Context, userID string, cutoff int64) ([]UsageRow, error)
func (s *Store) AllUsersUsage(ctx context.Context, cutoff int64) ([]UserUsage, error)
```
By-day SQL (by-model = same with `GROUP BY m.model`; totals = no GROUP BY;
all-users = `GROUP BY c.user_id` joined to `users` for `username`):
```sql
SELECT strftime('%Y-%m-%d', m.created_at/1000, 'unixepoch') AS day,
       COALESCE(SUM(m.prompt_tokens),0), COALESCE(SUM(m.completion_tokens),0),
       COALESCE(SUM(m.cached_tokens),0), COALESCE(SUM(m.reasoning_tokens),0),
       COALESCE(SUM(m.cost_micros),0), COUNT(1)
  FROM messages m JOIN conversations c ON c.id = m.conversation_id
 WHERE c.user_id = ? AND m.role = 'assistant' AND (? = 0 OR m.created_at >= ?)
 GROUP BY day ORDER BY day ASC
```
Keep the existing single-connection discipline (close rows before the next query).

### Indexing

### Quotas
Global settings (admin), `0` = off:
- `daily_token_limit` — total tokens (prompt+completion) per UTC day.
- `monthly_cost_limit` — `cost_micros` per UTC calendar month.

`main.go` `run()`: `EnsureSetting(ctx, "daily_token_limit", "0")` and
`EnsureSetting(ctx, "monthly_cost_limit", "0")` (next to the OCR default, :318).
`handlePatchSettings` (`users.go:224`) gains `DailyTokenLimit *int64`,
`MonthlyCostLimit *int64` (validate `>= 0`, persist as decimal string).
`usageSettings(ctx)` (self-contained block, like `ocrSettings`) returns both and
is merged in `writeSettings` (`users.go:344`).

Per-user overrides (optional): additive `users` columns
```go
{"users", "daily_token_limit", `ALTER TABLE users ADD COLUMN daily_token_limit INTEGER`},
{"users", "monthly_cost_limit", `ALTER TABLE users ADD COLUMN monthly_cost_limit INTEGER`},
```
`store.User` gains `DailyTokenLimit *int64`/`MonthlyCostLimit *int64`
(`json:"daily_token_limit,omitempty"`), added to `userCols`/`scanUser`/
`InsertUser`; new `SetUserLimits(ctx, id string, daily, monthly *int64, now int64)`.
`PATCH /api/users/{id}` accepts both as nullable numbers via a small presence-
tracking type so **omitted = unchanged, `null` = clear/inherit, number =
override**. Resolution:
```go
// effectiveLimits prefers a per-user override over the global admin setting.
func (s *Server) effectiveLimits(ctx context.Context, u store.User) (dailyTokens, monthlyCostMicros int64)
```

### Enforcement point (`internal/server/chat.go`)
Add a single helper and call it **before any upstream call and before the user
message is persisted**, so a rejection is a clean JSON error (no SSE bytes):
```go
// checkQuota returns a non-nil error when the user has hit a configured quota.
// It is cheap: it runs only when a limit is set, using start-of-UTC-day/month.
func (s *Server) checkQuota(ctx context.Context, u store.User) error
```
- `handlePostMessage`: call after `resolveKey` (`chat.go:91`), before building
  `userMsg` (:96). (So no orphan user message is stored on rejection.)
- `handleRegenerate`: call after `resolveKey` (`chat.go:132`), before
  `DeleteAssistantAfterLastUser` (:137).
- Logic: `daily, monthly := s.effectiveLimits(...)`; if both 0 return nil. If
  `daily > 0`, `t,_ := s.st.UserUsageTotals(ctx, u.ID, startOfUTCDay(now))`; if
  `t.PromptTokens+t.CompletionTokens >= daily` → error. If `monthly > 0`,
  `t,_ := UserUsageTotals(ctx, u.ID, startOfUTCMonth(now))`; if
  `t.CostMicros >= monthly` → error. Fail **open** on a DB error (log warn) so a
  transient fault cannot lock users out.
- Error response: `writeError(w, http.StatusTooManyRequests, msg)` with
  `msg` e.g. `"daily token limit reached (N tokens); resets at 00:00 UTC"` /
  `"monthly cost limit reached ($X.XX); contact an admin"`.

### Retention interaction
The janitor purges conversations older than `MYOGCHAT_RETENTION_DAYS`
(default 30, max 60) by `updated_at`, cascading messages (`main.go:429`), so
`range=all`/`30d` only cover retained data. A **monthly** quota is exact only
when retention ≥ the current month (with a 7-day window it undercounts); a
**daily** quota is always safe (retention min 1 day). Active conversations keep
all messages regardless of age, so a long chat can contribute
older-than-retention usage — acceptable at personal scale. Future option (out of
scope): a `usage_daily` rollup written before purge. Document in
`docs/2.11-usage.md`.

### Edge cases
- Free models: `cost_micros == 0`, so monthly cost limits never trip; the daily
  **token** limit still applies.
- `range` unknown/absent → `30d`.
- Admin sees only aggregates (§9.5: admins don't read others' chats).
- Per-user override `0` = "inherit" (can't force "unlimited" when a global limit
  is set) — documented limitation of the simple nullable-int scheme.
- Quota check adds ≤2 indexed SUM queries per send, **only when a limit is set**.
