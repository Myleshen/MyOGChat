# Feature 3.4 — Maps: research & scoping report

**Scope:** geocoding, reverse geocoding, directions, and places, exposed as `maps_*`
tools over the existing 2.4 tool loop. Owner wants **both** Google Maps and
"organic"/open-source maps.

**Bottom line:** Ship a provider layer mirroring `SearchProvider`
(`internal/tools/search.go`): a `GeoProvider` interface with `Geocode` / `Reverse` /
`Directions` / `Places`, an **OSM implementation** (Nominatim + OSRM + Photon +
Overpass, all keyless) and a **Google implementation** (Geocoding + Routes + Places
New, keyed). Default `auto` = **Google when a key is configured, otherwise OSM**;
explicit `osm`/`google` overrides. Effort ~3–4 dev-days (TODO calls it "small–medium").

## 2. Google Maps Platform

### 2.1 API mapping

| Need | API | Method / endpoint | Auth |
|---|---|---|---|
| Address → coords | **Geocoding API** (v3, also v4 now GA) | `GET https://maps.googleapis.com/maps/api/geocode/json?address=…` | `key=` query param |
| Coords → address | Geocoding API (reverse) | `GET …/geocode/json?latlng=…` | `key=` |
| Turn-by-turn directions | **Routes API** `computeRoutes` (replaces Directions API) | `POST https://routes.googleapis.com/directions/v2:computeRoutes` | `X-Goog-Api-Key` header + `X-Goog-FieldMask` |
| Distance/duration matrix | Routes API `computeRouteMatrix` (replaces Distance Matrix) | `POST https://routes.googleapis.com/distanceMatrix/v2:computeRouteMatrix` | same |
| POI search by text | **Places API (New)** Text Search | `POST https://places.googleapis.com/v1/places:searchText` | `X-Goog-Api-Key` + `X-Goog-FieldMask` |
| POI search near a point | Places API (New) Nearby Search | `POST https://places.googleapis.com/v1/places:searchNearby` | same |

**Shapes.**
- Geocoding response: `{"status":"OK","results":[{"formatted_address","geometry":{"location":{"lat","lng"}},"place_id","address_components":[…],"types":[…],"partial_match"?}]}`. Status codes: `OK`, `ZERO_RESULTS`, `OVER_QUERY_LIMIT`, `OVER_DAILY_LIMIT`, `REQUEST_DENIED`, `INVALID_REQUEST`, `UNKNOWN_ERROR`.
- Routes `computeRoutes` request: `{"origin":{"location":{"latLng":{"latitude","longitude"}}},"destination":{…},"travelMode":"DRIVE","routingPreference":"TRAFFIC_AWARE","units":"METRIC"}`; response `{"routes":[{"distanceMeters":772,"duration":"165s","polyline":{"encodedPolyline":"…"}}]}`.
- Places (New) Text Search request: `{"textQuery":"…","pageSize":5,"locationBias":{"circle":{"center":{"latitude","longitude"},"radius":500}}}`; response `{"places":[{"id","displayName":{"text"},"formattedAddress","location":{"latitude","longitude"},"types":[…]}]}`.
- **Field masks are mandatory** on Routes/Places (New): omit `X-Goog-FieldMask` → error; `*` is discouraged in production. Billing tier is chosen by which fields you request.

### 2.2 Places "New" vs legacy

- Legacy Places API is **frozen** (no new features, not eligible for new volume tiers); new Cloud projects can't enable it. New uses POST + JSON body + `X-Goog-Api-Key` header + field masks; legacy used GET + query params + `key=`.
- New billing is **SKU-tiered by requested fields**: `id`-only = Text Search Essentials; `displayName`/`formattedAddress`/`location` = Text Search **Pro**; ratings/hours/phone = **Enterprise**; reviews/menu/etc = **Enterprise + Atmosphere**. Requesting only Essentials/Pro fields keeps cost at the cheap tier.
- Same legacy→new story for **Directions → Routes** and **Distance Matrix → Routes `computeRouteMatrix`** (moved to Legacy status March 2025).

### 2.3 Pricing & free tier (2026 model)

The old universal **$200/month credit was retired in March 2025**; replaced by
**per-SKU monthly free tiers that do not pool**. Relevant SKUs:

| SKU | Free / month | First paid band / 1,000 |
|---|---|---|
| Geocoding | 10,000 | $5.00 |
| Directions (legacy SKU) / Routes Compute Routes | 10,000 | $5.00 (Basic) / $10 (Advanced) / $15 (Preferred) |
| Distance Matrix / Compute Route Matrix | 10,000 elements | $5.00 |
| Places Autocomplete Requests | 10,000 | $2.83 |
| Places Place Details Essentials | 10,000 | $5.00 |
| Places Nearby Search Pro | 5,000 | $32.00 |
| Places Text Search Pro | 5,000 | $32.00 |
| Places Place Details Pro | 5,000 | $17.00 |

Free tiers reset monthly, don't roll over, aren't transferable across SKUs. For a
personal app the free tiers are generous.

### 2.4 Rate limits, billing, key restrictions

- **Billing account is required** for all Google Maps Platform web services; calls fail (`OVER_DAILY_LIMIT`) without it.
- Geocoding rate limit: **3,000 queries/minute** (≈50 QPS), summed client+server. Daily quota caps are self-configurable in Cloud Console.
- **Key restrictions (mandatory best practice):** one key per app; apply an **application restriction** (HTTP referrer / IP / Android / iOS) **and API restrictions** (allow only the specific APIs). For a server-side Go binary the correct application restriction is **IP address** (the Pi's egress IP — via the Cloudflare tunnel this is Cloudflare's, which complicates IP restriction; see pitfalls §7). Unrestricted keys get billed for third-party abuse. Restrictions can take ~5 min to apply.
- **ToS caching limits:** lat/lng from Geocoding/Places may be cached only **up to 30 consecutive days**.
- **Places content must not be used with a non-Google map.**

## 3. Open-source / keyless providers

### 3.1 Nominatim (geocoding + reverse)

- Endpoints: `GET https://nominatim.openstreetmap.org/search?q=<query>&format=jsonv2&limit=5&countrycodes=us` and `GET https://nominatim.openstreetmap.org/reverse?lat=<>&lon=<>&format=jsonv2`.
- Returns JSON: search → array of `{place_id, lat, lon, display_name, type, class, address{…}, boundingbox}`; reverse → single object.
- **Usage policy (hard requirements):**
  - **Max 1 request/second** (absolute), applies to the sum of all your users.
  - **Valid `User-Agent` or `Referer` identifying the app** (stock library UAs are rejected).
  - **Display attribution** and ODbL share-alike applies.
  - **Cache results; set up a proxy**; apps must be able to switch servers without a software update.
  - **Autocomplete is forbidden**; systematic/bulk/grid queries forbidden; no scraping details pages; no reselling.
  - **LLM clause:** an LLM may only suggest Nominatim if it prominently points to the policy and its restrictions.
- Public server is donated/limited; heavy or commercial use → self-host or a third-party provider.

### 3.2 OSRM (directions/routing)

- Endpoint: `GET https://router.project-osrm.org/route/v1/{profile}/{lon,lat};{lon,lat}?overview=false&steps=false&geometries=geojson`. `profile` ∈ `driving|bike|foot` (each is a separately-prepared graph). Also `nearest`, `table` (matrix), `match`, `trip`.
- Response: `{"code":"Ok","routes":[{"distance":<m>,"duration":<s>,"geometry":…}],"waypoints":[…]}`. Note `table` gives matrix distances/durations (the keyless Distance Matrix equivalent).
- **Public demo server is explicitly not for production**: "may be offline or overloaded anytime … should not be abused." No formal SLA/rate limit, but heavy use is discouraged. `router.project-osrm.org` is run by FOSSGIS.
- Self-host: `osrm-backend` Docker images; prepare a regional OSM extract (e.g. Geofabrik). Car profile graph for a country is a few GB RAM/disk — fine for the Pi only for a small region; a full planet is not.

### 3.3 Photon (Komoot — autocomplete-friendly)

- Endpoints: `GET https://photon.komoot.io/api/?q=<>&limit=5&lat=&lon=&lang=` and `GET https://photon.komoot.io/reverse?lon=&lat=`.
- Returns GeoJSON `FeatureCollection`; each feature has `geometry.coordinates:[lon,lat]` and `properties{name,street,city,state,country,postcode,osm_id,osm_value,…}`.
- Purpose-built for **typeahead/autocomplete** (typo tolerance, multilingual, priority-by-position). Terms: fair use, "extensive usage will be throttled", no availability guarantee. Self-hostable (OpenSearch backend).

### 3.4 Overpass API (POIs)

- Endpoint: `POST https://overpass-api.de/api/interpreter` with body `data=<Overpass QL>` (or `GET ?data=`).
- Returns `{"version":…,"elements":[{"type":"node|way|relation","id":…,"lat","lon","tags":{…},"geometry":[…]}],"osm3s":{…}}`. Query by bbox, tag, `around:radius`, name, etc.
- **Usage policy:** assume fine below **10,000 queries/day, <1 GB/day, <10 min total processing**; a *regularly scheduled* app should divide those by 100 (**<100 queries, <10 MB/day**). App traffic counts across all users. `User-Agent`/`Referer` required; cache; on **429/406 pause 30s**; no parallel scripts. Main instance is **overloaded**; alternates: `overpass.private.coffee` (no rate limit), VK Maps. Commercial use → self-host/paid.

### 3.5 OpenRouteService (keyed, free tier) — optional

- Endpoints (note domain migration): `POST https://api.heigit.org/openrouteservice/v2/directions/{profile}` (auth header `Authorization: <key>`), geocoding via Pelias `https://api.heigit.org/pelias/v1/search`. Old `api.openrouteservice.org` is deprecated.
- Free **Standard plan**: Directions 2,000/day (40/min), Geocoding 3,000/day (100/min), POIs 500/day (60/min), Matrix 500/day (40/min), Elevation 2,000/day. Key from `account.heigit.org`. Self-host = unlimited (Docker).
- Useful as a middle ground: keyed and dependable, but OSM data (ODbL) and no Google ToS constraints.

### 3.6 Self-hosting weight (for the Pi 4B)

| Service | Fit on Pi 4B | Notes |
|---|---|---|
| Nominatim | ✗ full planet (needs ~64 GB+ RAM); ✓ small country extract only | import is CPU-heavy; not worth it for personal use |
| OSRM | ✓ small region (city/state) | a few GB; separate graph per profile |
| Photon | ✗ (needs OpenSearch + large index) | not practical |
| Overpass | ✗ (huge) | not practical |

**Conclusion:** self-hosting is not worth it for a personal app. Use the public
keyless servers with caching + a 1 req/s limiter, and offer Google as the quality
upgrade.

## 4. Google vs OSM capability/pricing comparison

| Capability | Google | OSM keyless stack |
|---|---|---|
| Geocode | Excellent (rooftop precision, `place_id`) | Nominatim — good; weaker on POIs/parcels |
| Reverse | Excellent | Nominatim — good |
| Autocomplete | Places Autocomplete (session pricing) | Photon — designed for it (Nominatim forbids it) |
| Directions | Routes API; traffic-aware, transit, 2-wheel | OSRM — car/bike/foot; **no live traffic/transit** |
| Matrix | Routes matrix (billed per element, 625 max) | OSRM `table` (free) |
| POIs | Places (New) — rich fields, ratings, hours | Overpass (raw OSM tags) or ORS POIs |
| Auth | API key + billing account | none |
| Cost | free tiers per SKU, then $5–$32/1k | $0 (donations/policy limits) |
| Limits | 3,000 QPM; key restrictions | Nominatim 1 req/s; Overpass quotas |
| Data license | Google ToS (cache ≤30d; no non-Google maps) | ODbL (attribution + share-alike) |
| Reliability | high/SLA | best-effort; OSRM demo not for production |
| Setup friction | billing + key restriction | none |

## 5. Recommended provider abstraction

Mirror the search layer exactly:

```go
// internal/tools/maps.go
type LatLng struct{ Lat, Lon float64 }

type Place struct {
    Name, Address string
    Lat, Lon      float64
    Type, Source  string   // source = "google" | "osm" | "photon" | "overpass"
}

type Route struct {
    DistanceMeters  float64
    DurationSeconds float64
    Mode, Summary   string
    Polyline        string   // encoded; "" when not requested
    Steps           []string // optional turn-by-turn
    Source          string
}

type GeoOptions struct {
    Limit  int
    Region string // ccTLD/ISO, e.g. "us"
    Lang   string
    Units  string // metric | imperial
    Mode   string // driving | walking | cycling | transit
}

type GeoProvider interface {
    Name() string
    Geocode(ctx context.Context, query string, opts GeoOptions) ([]Place, error)
    Reverse(ctx context.Context, at LatLng, opts GeoOptions) (Place, error)
    Directions(ctx context.Context, from, to LatLng, opts GeoOptions) (Route, error)
    Places(ctx context.Context, query string, opts GeoOptions) ([]Place, error)
}
```

- **`googleProvider`** — Geocoding API, Routes `computeRoutes`, Places Text Search (New); holds the API key + `*http.Client` + `baseURL` (testable via `httptest`).
- **`osmProvider`** — Nominatim (`Geocode`/`Reverse`), OSRM (`Directions`), Photon or Overpass (`Places`). Holds `baseURL` fields per sub-service, a **global 1 req/s limiter** for Nominatim, and a cache hook.
- `GeoConfig{Provider, GoogleKey, Region, Units, Limit}` + `BuildGeoProviders(cfg) []GeoProvider` + `GeoActive(cfg)`, mirroring `BuildSearchProviders`.
- **Selection/fallback:** `auto` → `[google, osm]` when a key exists, else `[osm]`; `google` → `[google, osm]`; `osm` → `[osm]` (or `[osm, google]` if keyed). The chain is **never empty** (OSM needs no key) — same invariant as DDG in search. Fall back per method on error/empty.

**Default:** `auto`. Rationale: keyless works out of the box (project ethos, like
DuckDuckGo default), and adding a Google key transparently upgrades quality. For a
self-hosted personal app, `osm` alone is defensible and $0; document that OSM public
servers are best-effort and rate-limited, so aggressive caching + the 1 req/s
limiter are required. Make Google opt-in, never silently billable.

**Keyless-but-rate-limited tradeoff:** serialize all Nominatim/Overpass calls behind
a single token-bucket (1 req/s) + an in-memory/SQLite cache with TTL. The tool loop
is already sequential per turn, so a 1 req/s cap rarely hurts. Overpass backs off 30s
on 429. This keeps the app inside the acceptable-use envelope.

## 6. Go implementation

- **No new dependency needed.** `net/http` + `encoding/json` + `net/url` + `time` cover every provider (all return JSON). Google `encodedPolyline` can be decoded with a ~30-line pure-Go function, or just request OSRM `geometries=geojson` and skip decoding entirely. No CGO, arm64-clean.
- **Tool schemas** (discrete tools fit the existing style — `linkwarden_search`/`_save`):
  - `maps_geocode` — `{query*: string, region?: string, limit?: int}`
  - `maps_reverse` — `{lat*: number, lon*: number}`
  - `maps_directions` — `{origin*: string, destination*: string, mode?: "driving"|"walking"|"cycling"|"transit", units?: "metric"|"imperial"}`
  - `maps_places` — `{query*: string, near?: string, radius_m?: int, limit?: int, type?: string}`
  - *(Alternative: one `maps` tool with a `mode` enum. Rejected: schemas get conditional, and the model picks clearer semantics with discrete tools. 4 extra tool specs is acceptable.)*
  - `origin`/`destination`/`near` accept free text **or** `"lat,lon"`; geocode text first, then route.
- **Normalized result text** (fed back to the model), e.g. directions:
  `Route: 12.4 km · 18 min (driving) — A → B\n1. Head north …\nSource: OSRM (© OpenStreetMap contributors)`.
- **Settings:**
  - Env: `GOOGLE_MAPS_API_KEY`, `MYOGCHAT_MAPS_PROVIDER` (`auto|google|osm`), `MYOGCHAT_MAPS_REGION`, `MYOGCHAT_MAPS_UNITS`, `MYOGCHAT_MAPS_LIMIT`.
  - DB (admin, `GET/PATCH /api/settings`): `maps_provider`, `google_maps_key` (encrypted via `internal/secret`, mirroring `brave_key`), `maps_region`, `maps_units`.
  - Surface `google_maps_configured`, `maps_provider`, `maps_active` like `brave_configured`/`search_active`.
  - Reuse the global `tools_enabled` gate; no separate on/off needed.
- **Caching:** small SQLite table `geo_cache(key TEXT PRIMARY KEY, value TEXT, expires_at INTEGER)`; geocode/reverse keyed by normalized query+region; TTL ~7–30 days (Google ToS caps lat/lng at 30 days). A tiny LRU in front for hot repeats. This is what makes the keyless path policy-compliant.

## 7. Pitfalls

1. **Coordinate order.** OSRM wants `{lon},{lat}`; Google wants `latLng{latitude,longitude}`; Nominatim reverse takes `lat=`/`lon=`. Centralize conversion; add tests — this is the #1 bug source.
2. **Rate limits.** Nominatim 1 req/s absolute; Overpass <100 queries/day for a scheduled app and 429→30s backoff; Google 3,000 QPM. Use one global limiter for the OSM stack.
3. **Caching is mandatory, not optional.** OSM policy requires caching + a proxy for apps; Google ToS allows lat/lng caching only ≤30 days. One cache satisfies both with a conservative TTL.
4. **Attribution/licensing.** OSM = ODbL: display "© OpenStreetMap contributors" and honor share-alike. Google requires Google branding and forbids using **Places** content with a non-Google map. Since MyOGChat renders no map, this is mostly a text-attribution + "don't mix Places content with a Leaflet map" concern.
5. **SSRF / prompt-injection.** Never accept a URL from the model; only call the fixed provider hosts. The tool args are query strings/coords — validate `-90≤lat≤90`, `-180≤lon≤180`, cap lengths. Same discipline as `fetch_url`.
6. **Google key restrictions vs Cloudflare tunnel.** Server-side keys should be IP-restricted, but the Pi's egress via Cloudflare Tunnel may present Cloudflare IPs to Google, making IP restriction awkward. Mitigation: restrict the key to only the needed APIs, set a low daily quota cap, and/or route Maps calls from a stable egress. Document this in Settings.
7. **Field masks / SKU cost.** Places (New) requires `X-Goog-FieldMask`; request only Essentials/Pro fields (`displayName,formattedAddress,location`) to stay on the cheap tier. Never use `*`.
8. **Transit.** OSRM has no transit; only Google Routes supports it. Surface a clear "transit requires Google" message instead of a silent wrong answer.
9. **Demo-server reliability.** OSRM demo and Nominatim/Overpass public instances can be down/overloaded; the fallback chain plus a clear "maps provider unavailable" error must be graceful. Consider `overpass.private.coffee` for POIs.
10. **Multi-user.** Follow the search pattern: a single admin-configured Google key (not per-user), encrypted at rest; users never see the key.

## 9. Recommendation

1. Build the **provider layer first** (interface + OSM impl), ship `maps_*` tools on
   keyless OSM alone — usable immediately, $0, no account.
2. Add the **Google impl + encrypted key setting** as a drop-in quality upgrade;
   default `auto` picks Google only when a key is present.
3. Add the **cache + 1 req/s limiter** in the same PR as the OSM impl — it's a policy
   requirement, not an optimization.
4. Use **4 discrete tools**; document attribution and the transit/Google caveat in
   the tool descriptions.
5. Defer self-hosting; it isn't practical on the Pi 4B.
