# Scope 2.12 — Serper.dev + Brave `llm/context` search providers

Status: research + scoping only (no code changed). Repo: `~/dev/myogchat`.
Baseline: `internal/tools/search.go` (2.4 provider layer), `docs/2.4-search-providers.md`,
`API_CONTRACT.md` §8.9 / §9.4.

## TL;DR

- **Serper** is a clean fit for the existing `SearchProvider` interface: one `POST`,
  `X-API-KEY` header, `organic[]` → `Result{Title,URL,Snippet}`. Add it as a 4th
  provider, same shape as Tavily/Brave. New env `SERPER_API_KEY`, DB `serper_key`.
- **Brave `llm/context`** should be a **mode on the existing Brave provider**, *not* a
  separate provider: same key, same host, same provider identity. Flatten
  `grounding.generic[].snippets[]` into the existing `Result.Snippet`. The model-facing
  `web_search` tool stays 100% unchanged (transparent).
- Proposed chain: **Tavily → Brave → Serper → DuckDuckGo** (`auto`), configurable.
  Bump `maxSearchChain` 3 → 4; revisit the 25s `searchBudget` vs 20s per-provider timeout.
- Effort: **~1 focused day** (6–8h) incl. tests/docs; plus the UI battery run.

## 1. API facts — Serper.dev

Primary refs: Serper OpenAPI (`api-evangelist/serper`), `serper.dev/terms`,
`apis.io/schemas/serper/serper-search-request`, LangChain `GoogleSerperAPIWrapper`,
LiteLLM `docs/search/serper`, `apio.sh/apis/serper`.

| Item | Value |
|---|---|
| Endpoint | `POST https://google.serper.dev/search` |
| Auth | header `X-API-KEY: <key>` (+ `Content-Type: application/json`) |
| Body | `{ "q": "...", "num": 10, "gl": "us", "hl": "en", "tbs": "qdr:d", "page": 1, "autocorrect": true, "location": "...", "type": "search" }` |
| `q` | required, string |
| `num` | results 1–100, default 10 |
| `gl` / `hl` | ISO-3166-1 alpha-2 country / ISO-639-1 language |
| `tbs` | time filter `qdr:h|d|w|m|y` (past hour/day/week/month/year) |
| `page` | pagination, default 1 |
| Response | `{ searchParameters, organic[], answerBox?, knowledgeGraph?, peopleAlsoAsk?, relatedSearches? }` |
| `organic[]` | `{ title, link, snippet, position, date?, sitelinks?, attributes? }` — note `link` (not `url`), `position` 1-based |
| `answerBox` | `{ answer?, snippet?, title?, link?, date? }` (featured answer) |
| `knowledgeGraph` | `{ title?, type?, website?, description?, descriptionSource?, descriptionLink?, attributes? }` |
| Errors | `400` bad request, `401` invalid/missing key, `429` rate limit / credits exhausted |

**Pricing** (credit-based, packs valid 6 months; only successful queries bill):
2,500 free queries one-time on signup → Starter $50/50k ($1.00/1k) → Standard $375/500k
($0.75/1k) → Scale $1,250/2.5M ($0.50/1k) → Ultimate $3,750/12.5M ($0.30/1k).
**Credit rule:** 10 results = 1 credit; **20–100 results = 2 credits**. Our tool clamps
to ≤20, so `num` 11–20 doubles cost — cap at 10 (or accept 2 credits).

**Rate limits:** 50 QPS (Starter) → 100 (Standard) → 200 (Scale) → 300 (Ultimate);
higher on request. **429** on breach; docs give no retry guidance.

**ToS notes:** B2B only, no end-user service; governed by **UK law**; **no SLA/uptime
commitment**; one account per person; **may not mirror/reproduce the data as-is with no
value added**; not affiliated/endorsed by Google; searches hit Google live (1–2s typical).
Personal, value-added agent use is fine.

## 2. API facts — Brave `llm/context`

Primary refs: `api-dashboard.search.brave.com/documentation/services/llm-context`,
`/api-reference/ai/llm_context/{get,post}`, `brave/brave-search-skills` `skills/llm-context`.

| Item | Value |
|---|---|
| Endpoint | `GET` **or** `POST https://api.search.brave.com/res/v1/llm/context` (same host as `braveBaseURL`) |
| Auth | header `X-Subscription-Token: <key>` — **same key/plan as web search** |
| Query params | `q` (required, 1–600 chars), `country` (2-char, default `us`), `search_lang` (default `en`), `count` (1–50, default 20), `freshness` (`pd|pw|pm|py|YYYY-MM-DDtoYYYY-MM-DD`) |
| Context params | `maximum_number_of_urls` (1–50, dflt 20), `maximum_number_of_tokens` (1024–32768, dflt **8192**), `maximum_number_of_snippets`, `maximum_number_of_tokens_per_url`, `maximum_number_of_snippets_per_url` |
| Filters | `context_threshold_mode` (`strict|balanced|lenient|disabled`), `safesearch` (`off|moderate|strict`), `enable_local`, `goggles`, `enable_source_metadata` |
| Response | `{ grounding: { generic[], map[] , poi? }, sources: { "<url>": {...} } }` |
| `grounding.generic[]` | `{ url, title, snippets: string[] }` — pre-extracted, relevance-ranked page chunks |
| `sources[url]` | `{ title, hostname, age[4]?, description?, site_name?, favicon?, thumbnail?, snippet? }` |

**Pricing:** all Web Search endpoints (incl. LLM Context) are **$5 per 1,000 calls/month**,
with **$5 free credits renewing monthly**. Rate limit is a **1-second sliding window**;
docs advise a 30s client timeout and exponential backoff on transient failures.

**Difference vs `/res/v1/web/search`:** web/search returns `web.results[]` with
title/url/**short description** (human SERP page). `llm/context` returns **extracted page
chunks** (`snippets[]`) + source metadata, data-first ranked for LLM consumption, with
token-budget/freshness/goggle controls. It is a *different retrieval mode*, but
mechanically it flattens to the same `Result` shape.

## 3. Concrete code changes

### 3.1 `internal/tools/search.go` — Serper provider

```go
const (
    SearchProviderSerper = "serper"
    serperBaseURL        = "https://google.serper.dev"
)

type SearchConfig struct {
    Provider     string // tavily | brave | serper | ddg | auto
    TavilyKey    string
    BraveKey     string
    SerperKey    string   // NEW
    BraveContext bool     // NEW — llm/context mode for Brave (see §4)
    MaxResults   int
    Region       string
    SafeSearch   string
}
```

- `NormalizeProvider`: add `case SearchProviderSerper: return SearchProviderSerper`.
- New `serperProvider{ apiKey, baseURL string; hc *http.Client }` + `newSerperProvider(key)`.
- `Search`: build `{"q":query,"num":clampResults(opts.MaxResults),"gl":countryFromRegion(opts.Region),"hl":langFromRegion(opts.Region)}`
  (`langFromRegion` = region suffix after `-`/`_`, default `"en"`), `POST baseURL+"/search"`,
  headers `X-API-KEY`, `Content-Type: application/json`. Decode:
  ```go
  var out struct {
      Organic []struct{ Title, Link, Snippet string } `json:"organic"`
      AnswerBox *struct{ Answer, Snippet string }     `json:"answerBox"`
      KnowledgeGraph *struct{ Title, Description string } `json:"knowledgeGraph"`
  }
  ```
  Map `organic` → `Result{Title, URL: Link, Snippet}`. Optional: prepend `answerBox`
  (answer/snippet + link) and/or `knowledgeGraph` description as a synthetic top result.
  Error on non-2xx (same `fmt.Errorf("serper: HTTP %d: %s", …)` pattern). Cap `num` at 10
  to stay at 1 credit (comment why).

## 4. Brave `llm/context`: provider vs mode → **mode**

Recommendation: **a mode/flag on the existing `braveProvider`**, configured by
`SearchConfig.BraveContext` (env `MYOGCHAT_BRAVE_MODE=web|context`, DB `brave_mode`).

Why not a separate provider:
- Same `Name()` identity would collide in the `usable` map and duplicate key handling;
  a distinct name (`brave_context`) would pollute provider selection/status semantics.
- It shares the exact same key, plan, and host (`braveBaseURL`), so it is not a distinct
  backend — it is a retrieval mode of the same backend.

Implementation:
- Change `newBraveProvider(apiKey string)` → `newBraveProvider(apiKey string, useContext bool)`;
  update the 3 call sites in `search_test.go`.
- `Search`: if `useContext`, hit `GET baseURL+"/res/v1/llm/context"` with
  `q`, `count=clampResults(opts.MaxResults)`, `country=countryFromRegion(opts.Region)`,
  `search_lang=langFromRegion(opts.Region)`, `safesearch`, and **smaller budgets**
  (`maximum_number_of_tokens=4096`) to keep tool output bounded. Decode:
  ```go
  var out struct {
      Grounding struct {
          Generic []struct{ URL, Title string; Snippets []string } `json:"generic"`
      } `json:"grounding"`
  }
  ```
  Map each entry → `Result{Title, URL, Snippet: strings.Join(Snippets, "\n")}`.
  Empty `grounding.generic` → provider error (so the chain continues), matching DDG's
  zero-result contract.
- Else: existing `/res/v1/web/search` path unchanged.

**Model-facing exposure: transparent.** `web_search` keeps its `{"query"}` schema; the
model simply receives richer snippets. No new tool, no schema change. (A separate
`web_context` tool is unnecessary for a single-user app and would double the surface.)

## 6. Pitfalls / notes

- **`maxSearchChain` / budget:** with 4 providers, cap 3 drops DDG. Raise to 4, but the
  25s budget vs 20s per-provider timeout means at most ~1–2 providers realistically run.
  Consider a shorter per-provider timeout for the chain or a larger budget.
- **Serper credits:** `num` 11–20 = 2 credits. Cap at 10 (comment why) or accept 2× cost.
- **Serper field names:** `link` not `url`; `position` 1-based; extras (`answerBox`,
  `knowledgeGraph`) are optional — prepending them changes result-count semantics.
- **Brave context payload size:** default 8192-token budget is far too large for a tool
  result. Set `maximum_number_of_tokens` (~4096) and keep `count` small. Snippets may be
  JSON-serialized structured data (tables/code) — fine for the model, but cap length.
- **gzip:** both APIs support gzip; leave `Accept-Encoding` unset so Go's transport
  negotiates/decompresses transparently (existing Brave behavior).
- **Region→lang:** add `langFromRegion` (Serper `hl`, Brave `search_lang`); default `en`.
- **Contract drift:** update `search_provider`/`search_active` unions and add
  `serper_configured`/`brave_mode`/`serper_key` in `API_CONTRACT.md` §9.4, or the UI
  contract test/frontend will disagree.
- **ToS/legal:** Serper is B2B, UK-law, no SLA, no data mirroring without value-add —
  acceptable for this personal, value-added agent, but worth a doc note.
- **Cache:** bump `static/sw.js` version or the new Settings fields can be masked.
