# Scope — Feature 2.13: Vision-model OCR (alternative OCR engine)

Repo `~/dev/myogchat` · research/scoping only (no code changed).
Goal: a `VisionModel` engine implementing the existing `internal/ocr.Engine`, so
an image can be transcribed by a multimodal OpenCode Go model instead of (or as a
fallback to) Docker Tesseract.

## 0. TL;DR / recommendation

- Add `internal/ocr.VisionModel` (implements `ocr.Engine`) that sends the image as
  an OpenAI-compatible content part and asks for **verbatim transcription**.
- Add one **non-streaming** helper to `internal/upstream` (`VisionOnce`) owning the
  two dialect shapes. OCR is a **single, non-tool** call — never the agent loop.
- Reuse `Server.resolveKey` for the key via a small `ocr.KeyedEngine` interface,
  bound inside `Server.ocrFunc`.
- Config `MYOGCHAT_OCR_ENGINE=tesseract|vision|auto`, **default `tesseract`**
  (free/local/private). `vision` = opt-in; `auto` = pick Tesseract at startup when
  Docker+image exist, else Vision. Keep vision opt-in (tokens + third-party image).
- Default vision model `deepseek-v4-flash-vision-exp` (chat, already registered,
  OCR-grade cheap); `gpt-6-luna` (responses) is the cheapest-input alternative.
- **Effort: medium (~1.5–2 days incl. tests/docs).**

## 2. Exact request shapes

Base `https://opencode.ai/zen/go/v1`. Headers (both): `Authorization: Bearer <key>`,
`Content-Type: application/json`, `x-opencode-session: <uuid>`, `User-Agent: myogchat/1.0`.

**2a. Chat Completions** (`deepseek-v4-flash-vision-exp`) — `content` is an array;
image is `image_url` with an object value; `detail` sits inside `image_url`:
```json
{"model":"deepseek-v4-flash-vision-exp","stream":false,"max_tokens":2048,
 "messages":[{"role":"user","content":[
   {"type":"text","text":"Transcribe all text in this image verbatim."},
   {"type":"image_url","image_url":{"url":"data:image/png;base64,iVBOR…","detail":"high"}}]}]}
```
Parse `choices[0].message.content`. Confirmed by the DeepSeek vision guide; opencode
issue #46345 confirms `image_url` works via the Go chat endpoint.

**2b. Responses** (`gpt-6-luna`) — `input` messages; text `input_text`, image
`input_image` with a **flat** `image_url` string and part-level `detail`:
```json
{"model":"gpt-6-luna","store":false,"stream":false,"max_output_tokens":2048,
 "input":[{"role":"user","content":[
   {"type":"input_text","text":"Transcribe all text in this image verbatim."},
   {"type":"input_image","image_url":"data:image/png;base64,iVBOR…","detail":"high"}}]}]}
```
Parse by concatenating `output[].content[].text` where `type=="output_text"` (the
top-level `output_text` is an SDK convenience, not guaranteed in raw JSON). Confirmed
by the OpenAI Responses vision guide + opencode issue #39888.

**Data URIs are accepted by both** (`data:image/...;base64,...`). DeepSeek detects
format from content, not MIME/name, and supports **JPEG/PNG/GIF/WebP** only — so
BMP/TIFF/PNM (which the extractor accepts) must be transcoded or rejected.

## 3. OCR prompt design

Return **only** the transcription (the extractor trims; empty → `ErrEmpty`).

System/instructions: *"You are a precise OCR engine. Transcribe ALL text visible
in the image exactly. Preserve the original language(s); never translate. Preserve
line breaks and reading order; approximate tables/columns with spaces/tabs. Do NOT
describe the image, add commentary, or answer questions. Output ONLY the
transcribed text, no preamble or code fences. If there is no readable text, output
nothing."* User part: the image + "Transcribe the text in this image."

Hallucination controls: `temperature: 0` where accepted; the explicit "output
nothing" clause; a post-filter that strips "Here is the text:"/fences and treats
refusals ("I can", "The image", "Sorry") as empty; bound with `max_tokens`.
Multi-language: instruct auto-detection; do **not** pass a language list
(`MYOGCHAT_OCR_LANGS` stays Tesseract-only).

## 4. Cost / limits / downscaling

- **DeepSeek**: resized to ~1300×1300-equivalent → **≤1024 tokens/image** regardless
  of size; inline body ≤48 MiB, single image ≤32 MiB, ≤8192 px/side; `detail: low`
  = 512×512, `high`/`original`/`auto` = original.
- **OpenAI** (`gpt-6-luna`): 32 px patches, 2,500-patch budget, **1.2×** multiplier,
  `high` ≤65,535 px; ≤20 MB/image, ≤500 images, ≤50 MB bytes/request.
- Uploads are capped at **10 MB** (`maxAttachmentBytes`) → data URI ≤~13.3 MB, inside
  both providers' limits. A screenshot is **hundreds–~2,500 image tokens** → a
  fraction of a cent.
- **Downscaling**: not required (providers downscale) and stdlib has no resampler
  (`golang.org/x/image` = new dep; stdlib decodes PNG/JPEG/GIF only, not
  WebP/BMP/TIFF). Recommend **v1: no server-side downscaling**; optional
  `MYOGCHAT_OCR_MAX_IMAGE_DIM` with a small pure-Go box filter later.
- OCR runs at `POST /api/attachments`, not on a message → no `cost_micros` today;
  optionally log the vision usage.

## 5. Other vision providers (future)

OpenAI direct (`gpt-5.x`/`gpt-4.1`, same Responses shape), Google Gemini
(`inline_data`/`mime_type`/`media_resolution`, different shape), Anthropic
(`image`+`source{base64}`, used by the Go `messages` models). All are localized to
`internal/upstream`; the `ocr.Engine` seam is unchanged.

## 6. Scoping against the code

Pipeline (unchanged): `POST /api/attachments` →
`extract.ExtractWith(name, mime, data, s.ocrFunc(ctx))` → `ocr.Func(ctx, engine)` →
`Engine.OCR(ctx, image)`. `internal/extract` stays Docker/network-free.

**6a. `internal/upstream/vision.go` (new)** — owns the wire shapes:
```go
type VisionRequest struct {
    Dialect, Model, SessionID, APIKey string
    Prompt, ImageURL                  string // ImageURL = data URI
    MaxTokens                         int    // 0 -> 2048
    Detail                            string // "", "low", "high", "original", "auto"
}
// VisionOnce sends one image + prompt and returns the assistant text.
// Single non-tool call (no agent loop, no streaming).
func (c *Client) VisionOnce(ctx context.Context, req VisionRequest) (string, error)
```
Switch on `Dialect` to build §2 payloads, reuse unexported `c.do`, read ≤1 MiB, parse
chat (`choices[0].message.content`) / responses (`output[].content[].text`). Per-call
timeout ~90 s (shorter than `streamTimeout`'s 5 min — the user is waiting).

**6b. `internal/ocr/vision.go` (new)** — the engine:
```go
type VisionClient interface { // slice of upstream.Client; fakeable
    VisionOnce(ctx context.Context, req upstream.VisionRequest) (string, error)
}
type VisionConfig struct {
    Client    VisionClient
    Model     string // vision-capable id
    Dialect   string // "chat" | "responses"
    APIKey    string // per request via WithKey
    SessionID string
    Prompt    string // overrides DefaultVisionPrompt
    MaxTokens int
    Detail    string        // default "high"
    Timeout   time.Duration // default ~90s
}
type VisionModel struct{ cfg VisionConfig }
func NewVisionModel(cfg VisionConfig) *VisionModel
func (v *VisionModel) OCR(ctx context.Context, image []byte) (string, error)

// KeyedEngine is an Engine that needs a per-request API key.
type KeyedEngine interface {
    Engine
    WithKey(apiKey, sessionID string) Engine // returns a bound copy
}
func (v *VisionModel) WithKey(apiKey, sessionID string) Engine
```
`OCR`: reject empty image; require `APIKey`; sniff MIME (PNG/JPEG/GIF/WebP magic,
default `image/png`); base64 → data URI; call `VisionOnce`; `TrimSpace`. Errors
wrap as `fmt.Errorf("vision OCR: %w", err)` → `extract.ErrOCR` →
`400 "could not read text from the image: …"`. `ocr → upstream` has no import cycle.

**6c. `internal/ocr/select.go` (new)** — selection + fallback:
```go
type FallbackEngine struct{ Primary, Secondary Engine }
func (f *FallbackEngine) WithKey(apiKey, sessionID string) Engine // propagates to keyed children
func SelectEngine(mode string, tess, vision Engine) Engine         // tesseract|vision|auto
```
Add sentinel `ocr.ErrUnavailable` (docker binary/daemon/image missing) so fallback
triggers on *unavailability*, not on every failure (don't pay for vision just
because Tesseract found no text).

**6d. `internal/server/ocr.go`** — bind the key (attachments.go already has `u`):
```go
// before: ocrFunc(ctx) ; after:
func (s *Server) ocrFunc(ctx context.Context, u store.User) ocr.OCRFunc {
    if s.ocrEngine == nil || !s.ocrSettingEnabled(ctx) { return nil }
    eng := s.ocrEngine
    if ke, ok := eng.(ocr.KeyedEngine); ok {
        key, err := s.resolveKey(ctx, u) // BYOK → group → shared server key
        if err != nil {
            return func([]byte) (string, error) { return "", err } // → ErrOCR
        }
        eng = ke.WithKey(key, newUUID())
    }
    return ocr.Func(ctx, eng)
}
```
Call site `internal/server/attachments.go:81` →
`extract.ExtractWith(name, mimeType, data, s.ocrFunc(r.Context(), u))`. `Server` keeps
one `ocrEngine ocr.Engine`; the engine is built once, the key injected per request
(group/server keys honored automatically).

**6e. `internal/models/models.go`** — add `Vision bool \`json:"vision"\`` and set it for
the confirmed set (the only clean way to know a model is vision-capable; lets
`main.go` validate `MYOGCHAT_OCR_VISION_MODEL` and optionally expose `vision`).

**6f. `main.go`** — new env + wiring:
| Env | Default | Meaning |
|---|---|---|
| `MYOGCHAT_OCR_ENGINE` | `tesseract` | `tesseract`\|`vision`\|`auto` |
| `MYOGCHAT_OCR_VISION_MODEL` | `deepseek-v4-flash-vision-exp` | model id |
| `MYOGCHAT_OCR_VISION_DETAIL` | `high` | `low`\|`high`\|`original`\|`auto` |
| `MYOGCHAT_OCR_VISION_MAX_TOKENS` | `2048` | output cap |
| `MYOGCHAT_OCR_VISION_TIMEOUT` | `90s` | per-call (`90s`/`90`) |
| `MYOGCHAT_OCR_MAX_IMAGE_DIM` | `0` | 0 = no downscale |

```go
var tess ocr.Engine
if cfg.ocrEnabled { tess = ocr.NewDockerTesseract(...) }
var vision ocr.Engine
if m, ok := models.ByID(cfg.ocrVisionModel); ok && m.Vision {
    vision = ocr.NewVisionModel(ocr.VisionConfig{Client: upstream.NewClient(),
        Model: m.ID, Dialect: m.Dialect, MaxTokens: cfg.ocrVisionMaxTokens,
        Detail: cfg.ocrVisionDetail, Timeout: cfg.ocrVisionTimeout})
}
ocrEngine := ocr.SelectEngine(cfg.ocrEngine, tess, vision)
```
`auto` preflights Docker at startup (PATH + `docker image inspect <OCR_IMAGE>`):
present → Tesseract (with Vision as fallback), absent → Vision (or nil).

**6g. Settings/API** — reuse the admin `ocr_enabled` gate; extend `ocrSettings` with
read-only `ocr_engine` (`"tesseract"|"vision"|"auto"|"none"`) and
`ocr_vision_available` in `GET /api/settings` (§9.4). Optional admin `ocr_engine`
selector stored like `search_provider`. Update `API_CONTRACT.md §8.10` + a new
`docs/2.13-vision-ocr.md`.

## 7. Default vs fallback — recommendation

Keep **`tesseract` the default** (free, local, private, already deployed). Vision
costs tokens, adds latency, and ships the image to a third party — an opt-in privacy
change. Offer `vision` for explicit use (handwriting, figures, multi-language, no
Docker) and `auto` for resilience: decide at **startup** (predictable), not per
request. When no key resolves, error clearly rather than silently failing.

## 9. Pitfalls

- **base64 size:** 10 MB → ~13.3 MB data URI; fine for both providers but duplicates
  RAM on the Pi.
- **Unsupported formats:** vision accepts JPEG/PNG/GIF/WebP only; transcode BMP/
  TIFF/PNM (needs non-stdlib decoders) or reject / fall back to Tesseract.
- **Timeouts:** short per-call context (~90 s) bound to `r.Context()` so a disconnect
  cancels upstream; don't inherit the 5-min stream timeout.
- **Single-shot:** `VisionOnce` only — never `StreamAgent`/`Stream` (no tools, no
  reasoning loop).
- **Reasoning:** responses defaults to `effort:"medium"`; DeepSeek may think. Ignore
  `reasoning_content`, take the final text; disable thinking if the gateway allows.
- **Error mapping:** engine errors → `extract.ErrOCR` → 400 "could not read text…";
  a missing key is currently indistinguishable from a model failure.
- **Privacy/cost:** the image leaves the device and spends tokens — document it.
- **Import direction:** `ocr → upstream` only; keep wire format in `upstream`.
- **`detail`:** use `high`/`original` for OCR (small text); `low` is cheaper but lossy.
