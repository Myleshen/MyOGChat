# Feature 3.2 — IMAP Email (Gmail / iCloud / Zoho) — Research Report

Scope: read/search/send mail from a connected mailbox, exposed as `email_*` tools + a Settings section.
Constraints assumed: single Go binary, `CGO_ENABLED=0`, pure-Go deps only, embedded vanilla-JS SPA,
multi-user, secrets encrypted via `internal/secret` (AES-256-GCM), runs on a Pi 4B.

---

## TL;DR / Recommendation

1. **Use app-specific passwords as the primary auth mechanism, not OAuth2.** All three providers
   support app passwords, and for a self-hosted single-user app OAuth2 for Gmail is a trap (see §2/§3).
2. **Ship Gmail + iCloud + Zoho via a generic IMAP/SMTP config**, with per-provider presets.
3. **Libraries:** `github.com/emersion/go-imap/v2` + `go-message` + `go-sasl` (all MIT, pure Go) for
   reading; `net/smtp` (stdlib, BSD-3) for sending. No CGO anywhere.
4. **Per-user mailbox credentials**, stored in the existing encrypted secret store, one mailbox per user.
5. **Effort: Medium.** Recommend scoping v1 to `email_search` / `email_read` / `email_folders` / `email_send`,
   read + send, app-password auth, with a confirmation gate on send.

### Notes per provider

**Gmail**
- Plain username/password IMAP/SMTP is fully disabled. Only **app passwords** (with 2SV) or **OAuth2** work.
- Google's own docs still document app passwords as available but "not recommended"; third-party blogs
  claim a 2026 app-password phase-out — **unverified/unreliable marketing**, not in Google's primary docs.
  Treat app passwords as supported but add OAuth2 later if Google deprecates them.
- Folder names: `[Gmail]/All Mail`, `[Gmail]/Sent Mail`, `[Gmail]/Drafts`, `[Gmail]/Spam`,
  `[Gmail]/Trash`, `[Gmail]/Starred`, `[Gmail]/Important`. **Do not hardcode** — use RFC 6154 SPECIAL-USE
  attributes (`\All`, `\Sent`, `\Drafts`, `\Junk`, `\Trash`, `\Flagged`, `\Important`).
- Labels are folders; one message can appear in several. Dedup with the `X-GM-MSGID` extension.
- Extensions: `IDLE`, `UIDPLUS`, `SASL-IR`, `NAMESPACE`, `QUOTA`, `SPECIAL-USE`, `X-GM-EXT-1`
  (`X-GM-RAW` full Gmail search syntax, `X-GM-MSGID`, `X-GM-THRID`, `X-GM-LABELS`). `XLIST` is deprecated.
- **Sending via Gmail SMTP auto-saves a copy to `[Gmail]/Sent Mail`** — do NOT also APPEND (duplicate).

**Apple iCloud Mail**
- App-specific password is the only practical path. Generate at account.apple.com → Sign-In and Security →
  App-Specific Passwords; max 25 active; **all revoked when the Apple ID password changes**.
- No POP. No public OAuth client registration for third-party IMAP.
- Folder names: `INBOX`, `Sent`, `Drafts`, `Trash`, `Archive`, `Junk`. Use SPECIAL-USE where advertised.
- **SMTP send does NOT auto-save to Sent** → you must `APPEND` the sent message to `Sent` yourself.

**Zoho Mail**
- Must **enable IMAP Access** in Settings → Mail Accounts → primary address first.
- **Critical caveat: IMAP/POP/SMTP is no longer included on newly-signed-up Free plans** — paid plans only.
  Verify the owner's plan before promising Zoho support.
- Auth: account password (2FA off) or app-specific password (2FA on); OAuth2 also supported.
- Folder names: `INBOX`, `Sent`, `Drafts`, `Spam`, `Trash`, `Archive` (varies; use SPECIAL-USE / LIST).
- **SMTP send does not reliably auto-save to Sent** → `APPEND` to Sent.
- Rate limits are hourly/dynamic (50–500/hour), stricter than Gmail.

## 2. Recommended auth approach

**App-specific passwords (SASL PLAIN over implicit TLS) for all three providers.** Rationale:

- Works for 100% of the target providers today; iCloud has no alternative.
- Pure-Go, trivial to implement (`Login`/PLAIN), no token refresh, no HTTP round trips, no browser flow.
- Fits a self-hosted PWA where each user pastes a password once into Settings.
- Avoids the Gmail OAuth consent/verification minefield (§3).

Design the credential record with an `auth_type` field (`password` | `oauth2`) so OAuth2 can be added
later for Gmail/Zoho without a schema migration. Start with `password`.

**OAuth2 is optional/later.** If added, do it per-user with the user supplying their own client
credentials (see §3) — do not ship a shared server-wide OAuth client.

## 3. OAuth2 specifics (only if you later add it)

**Gmail**
- Scope: `https://mail.google.com/` (restricted, full mailbox). No granular IMAP scope exists.
- SASL: `XOAUTH2` string `base64("user=" + email + "\x01auth=Bearer " + token + "\x01\x01")`.
  Gmail now also advertises `AUTH=OAUTHBEARER`, which `go-sasl` implements directly.
- Token endpoint `https://oauth2.googleapis.com/token`; access token ~1 h; refresh via `refresh_token`.
- **The trap:** an External OAuth consent screen in **"Testing"** status issues refresh tokens that
  **expire after 7 days** (unless only `openid`/`email`/`profile` scopes). Publishing an app that uses a
  restricted Gmail scope requires **Google verification** (security assessment) — impractical for a
  personal app. Practical workarounds: (a) app passwords, (b) a **Google Workspace internal** app, or
  (c) accept weekly re-auth. **This is why app passwords are the right default here.**

**Zoho**
- Register at `api-console.zoho.com` (Server-based Application). Auth `accounts.zoho.com/oauth/v2/auth`,
  token `accounts.zoho.com/oauth/v2/token`; pass `access_type=offline` to get a refresh token.
- Scopes are `ZohoMail.<resource>.<OP>` (e.g. `ZohoMail.messages.ALL`, `ZohoMail.folders.READ`).
  Access token ~3600 s; refresh token long-lived. Revoke: `accounts.zoho.com/oauth/v2/token/revoke`.
- For IMAP/SMTP SASL use the standard `XOAUTH2`/`Bearer` token (the `Zoho-oauthtoken` header prefix is
  for the REST API only).

**iCloud:** no OAuth2 for third-party IMAP. App-specific password only.

## 4. Go library recommendation

| Library | Version | License | Pure Go / CGO | Notes |
|---|---|---|---|---|
| `github.com/emersion/go-imap/v2` (`imapclient`) | `v2.0.0-beta.8` (Dec 2025) | MIT | ✅ pure Go | IMAP4rev2; clean command API; IDLE, UIDPLUS, SPECIAL-USE, streaming FETCH, `Authenticate(sasl.Client)` |
| `github.com/emersion/go-imap` (v1) | `v1.2.1` | MIT | ✅ pure Go | Stable but frozen, IMAP4rev1 only; conservative fallback |
| `github.com/emersion/go-message` (+ `mail`, `charset`) | latest | MIT | ✅ pure Go (deps `golang.org/x/text`) | RFC 5322/2045/2046/2047/2183, streaming MIME, attachment + charset handling |
| `github.com/emersion/go-sasl` | latest | MIT | ✅ pure Go | PLAIN, LOGIN, OAUTHBEARER (RFC 7628). **No XOAUTH2 type** — see below |
| `net/smtp` (stdlib) | Go 1.27 | BSD-3 | ✅ pure Go | Frozen (no new features) but functional; `PlainAuth` covers app passwords |
| `github.com/emersion/go-smtp` (alt) | latest | MIT | ✅ pure Go | Has a client with SASL if you need XOAUTH2 SMTP without an adapter |

**Recommendation:** `go-imap/v2` (pin the exact beta) + `go-message` + `go-sasl` for reading,
`net/smtp` for sending. All permissively licensed and CGO-free, so `CGO_ENABLED=0` is preserved.

**XOAUTH2 gotcha:** `go-sasl` ships **OAUTHBEARER only**, not `XOAUTH2`. For Gmail you can either use
OAUTHBEARER (Gmail supports it) or drop in a ~15-line custom `sasl.Client` producing the XOAUTH2
`user=…\x01auth=Bearer …\x01\x01` blob. `go-imap/v2`'s `Client.Authenticate(sasl.Client)` accepts either.
For `net/smtp`, `PlainAuth` is enough for app passwords; XOAUTH2 SMTP needs a small `smtp.Auth` adapter
(the `smtp.Auth` and `sasl.Client` interfaces differ).

## 5. Proposed design

### 5.1 Credential storage
Store one encrypted JSON blob per user under `internal/secret` (AES-256-GCM). Never return secrets to the SPA.

```json
{
  "provider": "gmail|icloud|zoho|custom",
  "email": "user@example.com",
  "auth_type": "password",
  "password": "<app-specific password>",
  "imap": { "host": "imap.gmail.com", "port": 993, "tls": "implicit" },
  "smtp": { "host": "smtp.gmail.com", "port": 587, "tls": "starttls" },
  "allow_send": true,
  "append_sent": true
}
```
For future OAuth2 add `refresh_token`, `client_id`, `client_secret`, `token_endpoint`.
`append_sent` = true for iCloud/Zoho, false for Gmail (auto-saved).

### 5.2 Connection handling
- **Per-call connect** (dial → auth → operate → logout) with `context` timeouts:
  ~15 s dial/TLS, ~30 s per operation, overall deadline ~60 s. Simple, robust on a Pi, low volume.
- Optional single cached connection per user with a short idle timeout (e.g. 60 s) if latency matters.
  If caching, use `NOOP` health-checks and reconnect on error. Skip IDLE for v1 (no push needed).
- Enforce TLS with certificate verification; never fall back to `DialInsecure`.
- Cap FETCH sizes; request only needed body sections (`BODY.PEEK[...]`) and mark messages `\Seen`
  deliberately rather than implicitly.

### 5.3 Normalized message model
```go
type Message struct {
    UID         uint32
    MessageID   string    // RFC 5322 Message-ID
    From        []Address
    To          []Address
    Cc          []Address
    Subject     string
    Date        time.Time
    Snippet     string    // first ~200 chars of text body
    BodyText    string    // truncated, e.g. 100 KB cap
    BodyHTML    string    // optional, truncated
    Attachments []Attachment // {filename, contentType, size, index} — bytes on demand
    Flags       []string
    Folder      string
}
```

### 5.4 Tool schemas (JSON Schema subset used by the tool loop)

```jsonc
// email_folders
{ "name": "email_folders", "description": "List mail folders/mailboxes for the user's connected mailbox.",
  "parameters": { "type": "object", "properties": {}, "required": [] } }

// email_search
{ "name": "email_search",
  "description": "Search the mailbox. Returns message summaries (uid, from, subject, date, snippet).",
  "parameters": { "type": "object", "properties": {
      "query":   { "type": "string", "description": "Free-text or Gmail-style query (X-GM-RAW on Gmail)" },
      "from":    { "type": "string" },
      "to":      { "type": "string" },
      "subject": { "type": "string" },
      "since":   { "type": "string", "description": "RFC3339 date" },
      "before":  { "type": "string", "description": "RFC3339 date" },
      "unread_only": { "type": "boolean", "default": false },
      "folder":  { "type": "string", "default": "INBOX" },
      "limit":   { "type": "integer", "default": 20, "maximum": 50 }
  }, "required": [] } }

// email_read
{ "name": "email_read",
  "description": "Read a single message by UID, including a truncated body and attachment metadata.",
  "parameters": { "type": "object", "properties": {
      "uid":    { "type": "integer" },
      "folder": { "type": "string", "default": "INBOX" },
      "include_html": { "type": "boolean", "default": false }
  }, "required": ["uid"] } }

// email_send  (gated — see §6)
{ "name": "email_send",
  "description": "Send an email from the user's connected mailbox.",
  "parameters": { "type": "object", "properties": {
```

Optional later: `email_mark_read`, `email_move`, `email_download_attachment` (with size cap).

## 6. Multi-user storage & settings design

- **Per-user mailbox credentials** (recommended). Each user connects their own mailbox in Settings;
  the app is multi-user and a server-wide mailbox would leak one person's mail to everyone.
- Settings section: provider picker (Gmail/iCloud/Zoho/Custom) → prefilled host/port/TLS → email +
  app-specific password → "Test connection" button → toggle "Allow sending" → save.
- Store the credential blob encrypted via `internal/secret`, keyed by user ID; scope it exactly like
  other per-user secrets. Add a `mailboxes` table (user_id, provider, email, secret_ref, allow_send,
  append_sent, created_at) if you want metadata queryable without decrypting.
- Never expose the password/refresh token back to the client; return only provider/email/status.
- Provide a "Disconnect mailbox" action that deletes the secret.

## 7. Security & pitfalls

- **Prompt injection is the #1 risk.** Email bodies are attacker-controlled. Wrap fetched content in
  clear delimiters, instruct the model that email content is untrusted data (never instructions), and
  **require explicit user confirmation before `email_send`**. Consider disabling `email_send` by default
  per user and requiring a Settings opt-in (`allow_send`).
- **Read-only vs send:** default to read/search; make send an explicit per-user permission. Optionally
  support a read-only IMAP login for users who never send.
- **Attachment caps:** cap message size (e.g. 10 MB) and per-attachment fetch (e.g. 5 MB); never
  auto-fetch attachment bodies — expose metadata and fetch on demand only.
- **Body truncation:** cap stored/returned body (e.g. 100 KB text) to protect the Pi's memory and the
  model context window.
- **Credential safety:** keep secrets in the AES-256-GCM store; never log them; ensure `%v`/error paths
  don't leak the password; force TLS cert verification.
- **Provider pitfalls:** Gmail duplicate-Sent if you APPEND after SMTP send; iCloud/Zoho missing Sent if
  you don't APPEND; Zoho Free plan has no IMAP; iCloud/Zoho/Gmail app passwords are revoked on password
  change (surface a clear "re-enter password" error); Gmail IMAP drops after ~24 h / ~1 h OAuth.
- **Search semantics differ:** Gmail supports `X-GM-RAW` full syntax; iCloud/Zoho only standard
  IMAP `SEARCH` keys — build the search tool to translate simple filters into standard keys and use
  `X-GM-RAW` only when the provider advertises `X-GM-EXT-1`.

## 8. Effort estimate & recommendation

**Effort: Medium.** Rough breakdown:
- Provider presets + generic IMAP/SMTP client wrapper: small.
- `go-imap/v2` + `go-message` read/search/list + MIME parsing: medium (the bulk).
- `net/smtp` send + Sent-folder APPEND logic: small.
- Settings UI (vanilla JS) + encrypted storage wiring: small–medium.
- Tool schemas + tool-loop integration + tests: small.
- Security hardening (injection guard, caps, confirmation): small.

Total: roughly 2–4 focused days for one developer; the MIME/HTML extraction and provider quirks are the
main unknowns.

**Recommendation:** Proceed with a **generic IMAP/SMTP implementation** driven by per-provider presets,
**app-specific-password auth**, **per-user credentials**, and the tool set
`email_folders` / `email_search` / `email_read` / `email_send` (send gated by explicit user opt-in).
Use `go-imap/v2` + `go-message` + `go-sasl` and `net/smtp`. Defer OAuth2; if you add it, do it
per-user and be aware of Gmail's 7-day testing-mode refresh-token expiry. Confirm the owner's **Zoho
plan includes IMAP** before advertising Zoho support.
